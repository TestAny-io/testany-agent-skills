# 本稿素材

S1 / 假设案例：一个 12 人团队使用工单、即时消息和共享文档三个工具。同一任务在三处被维护，交接时经常需要追问哪份状态有效。这只是用于解释问题的假设，不是调查结果或真实客户故事。

S2 / 作者观点：把任务状态的唯一维护位置写清楚，让其他地方链接到它，而不是重复维护。工具是否值得保留，应看它承担的独立职责和实际收益。

S3 / 作者建议：增加工具前先明确负责人、输入输出和与既有工具的关系；选一个小流程试运行；观察交接等待和重复输入是否减少，再决定推广。不要为了追求速度取消确有必要的批准。

S4 / 边界：不声称能节省某个百分比，不虚构行业研究，不评价具体公司，不把“工具越少越好”当成结论。
