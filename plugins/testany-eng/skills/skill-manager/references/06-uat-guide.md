## 打开与准备

默认入口：[打开 SkillDock](http://127.0.0.1:4771)。以启动器输出的实际 URL 为准，可在 Codex 右侧浏览器中打开。

启动需要 Node.js **22.12 或更新版本**及 npm。在本仓库根目录执行：

```sh
node plugins/testany-eng/skills/skill-manager/scripts/launch.mjs start
```

将末尾 `start` 换成 `status` 可查看状态，换成 `stop` 可停止本启动器管理的服务。首次启动会准备隔离运行目录、安装锁定依赖并构建。启动器的 start/status/stop 已通过隔离测试；本次实际实例的启动与访问结果另见[验证记录](05-verification.md)，不以隔离测试代替真实启动结果。

**UAT-01 至 UAT-11 在顶部「演练」环境进行；UAT-12 仅只读查看本机。** 演练使用独立真实文件并保存操作记录，刷新页面不会重置样例。重复验收时先确认样例当前状态；若缺失，记录受阻并由开发者补齐，不使用真实技能代替。

开始前请记录：日期、应用构建、浏览器、面板宽度、验收人。每项填「通过 / 不通过 / 受阻 / 未测」。

## 已提供的演练样例

| 用途 | 实际样例与入口 | 首次初始化状态 |
|---|---|---|
| 启用与禁用 | 技能库中的 `design-review`，卡片右下角开关 | 已启用，可独立操作 |
| 本地安装 | 安装技能 → 本地目录 → 填入本地演练示例 | 来源为 `release-notes`，尚未安装 |
| 更新与恢复 | 更新页的 `writing-assistant` → 检查更新 | 已安装正文含「第一版」；来源含「第二版」，并新增 `checklist.md` |
| 市场与插件 | 市场来源 → 添加来源 → 填入演练市场 | `community-market` 尚未添加，内含 `community-tools`；另有默认的 `starter-market` |
| Git 安装 | 安装技能 → Git 仓库 → 填入 Git 演练示例 | 本地 Git 来源含 `git-workflow`，无需联网；子目录与分支可留空 |
| 保护状态 | 技能库中的 `system-helper` | 系统内置演练样例，操作受保护 |

「查看目录」可查看当前环境的技能、配置、应用数据和项目路径。以上来源由后端生成，界面快捷按钮填入实际路径；不需要用户手工准备文件或修改版本。若本机未能初始化 Git，Git 样例不可用时将可选项记为受阻。

## 顺序验收

### UAT-01 打开与环境辨认

选择「演练」，浏览技能库、插件、市场来源、更新和操作记录，再返回技能库。缩窄右侧面板检查导航、环境选择和主要按钮。

期望：自动出现真实演练清单；五个页面标题清楚；始终能辨认环境，无空白崩溃或阻断性横向滚动。

### UAT-02 搜索与筛选

搜索 `design`；使用「全部来源」筛选和上方「已启用」「独立技能」「需要关注」统计卡，再恢复「全部技能」。输入不会匹配的词，点击「清除筛选」。分别使用工具栏的「卡片视图」和「列表视图」。

期望：结果和数量随条件变化，清除后恢复；搜索及时，空态说明清楚。

### UAT-03 详情与状态说明

打开 `design-review`，查看用途、来源、完整路径、状态证据及 SKILL.md，使用复制路径按钮；按 Esc 关闭。再查看 `system-helper` 的限制说明。如清单有同名或别名，核对对应路径。

期望：能确认操作对象；正文按文字展示；关闭后焦点回到原控件；受保护技能不会被误认为可独立删除。

### UAT-04 启用与禁用

关闭 `design-review` 卡片开关，刷新确认已禁用；再启用并刷新。到「操作记录」核对两次结果。

期望：配置读回与显示一致，记录对象准确；需要新会话或重载时有明确提示，不宣称已改变运行中的 Codex 会话。

### UAT-05 预览与安装

1. 点击「安装技能」→「本地目录」→「填入本地演练示例」→「预览技能」。
2. 核对 `release-notes` 的用途、文件规模与演练目标路径；先按 Esc 关闭，确认尚未安装。
3. 重复预览并点击「确认安装」，搜索 `release-notes`，打开详情核对来源及正文。

期望：预览不会直接安装；确认后清单及操作记录有结果，来源已记录。

### UAT-06 安装冲突与错误恢复

对同一 `release-notes` 来源再次预览、尝试安装，查看冲突后关闭；确认原技能及正文仍在。另开安装框，输入明显不存在的路径，查看错误，再用演练示例按钮修正来源。

期望：已有目标不被覆盖；错误不显示成功，原因可理解，其他页面仍可使用。

### UAT-07 更新、预览与恢复

1. 在「更新」找到 `writing-assistant`，点击「检查更新」。
2. 查看 SKILL.md 的修改和 `checklist.md` 的新增，点击「确认更新」。
3. 回技能库打开详情，确认正文含「第二版」，刷新后仍在。
4. 在操作记录找到本次「更新技能」，点击「恢复」→「确认恢复」。再查看详情，确认正文回到「第一版」。

期望：先展示变化再更新；实际正文与结果一致，恢复回到前版；未追踪技能为何不支持自动更新也有说明。

### UAT-08 移除、取消与恢复

打开已安装的 `release-notes` →「移除技能」，核对路径与恢复说明后先「取消」。再次操作并点击「移至可恢复区」，确认清单中消失；到操作记录点击本次移除的「恢复」→「确认恢复」，重新搜索并核对正文。

期望：取消无副作用；移除及恢复结果真实，恢复后来源仍正确；目标被占用时拒绝覆盖并说明冲突。

### UAT-09 市场与插件生命周期

1. 「市场来源」→「添加来源」→「本地市场」→「填入演练市场」→「添加来源」。
2. 在 `community-market` 卡片查看来源和数量，点击「浏览插件」。
3. 找到 `community-tools`，点击「安装插件」并确认；查看已安装状态及附带的 `community-tools-review` 技能。
4. 在插件卡片禁用、启用，每次刷新核对。
5. 点击「卸载」，核对确认框列出的受影响技能和路径，再「确认卸载」，检查插件与技能清单。

期望：插件按包管理，附带技能归属清楚；演练结果不会被描述为真实 Codex 插件已安装或卸载。

### UAT-10 市场移除与刷新说明

查看 `community-market` 来源卡片。本样例为本地目录，刷新按钮不可用；通过按钮提示及页面说明理解 Git 刷新范围。点击卡片的移除来源图标，核对影响说明后确认，在操作记录查看结果。

期望：本地目录不假装执行 Git 刷新；刷新市场不等于更新全部插件；移除来源不隐式卸载所有已安装包。本轮未提供 Git 市场刷新样例，该分支不记为用户已验证。

### UAT-11 操作记录、交互与环境切换

1. 核对成功、失败及恢复记录的对象、时间、结果。使用 Tab、Enter、Esc 操作搜索、详情和对话框，检查焦点是否清楚。
2. 打开演练详情或安装预览，**先按 Esc 关闭**，再切到「本机」，确认没有旧对象或预览残留；返回「演练」。对话框打开时遮罩会阻止点击环境选择，这是预期行为。
3. 点击「刷新」后趁读取中切换环境，再返回演练；检查最终清单与顶部环境一致。若读取太快而无法观察，记录该观察未测，异步竞态另以开发自动化证据核验。

期望：没有重复提交或跨环境结果串入，界面不会误操作上一个环境的对象；不支持的操作有原因。

### UAT-12 本机清单只读查看

切到「本机」，仅浏览、搜索、打开详情和页面导航。抽查熟悉的技能、来源及路径；查看系统、插件缓存和不可用操作的说明。随后返回演练，核对演练记录仍在。

期望：信息真实，不将缓存当作已核实安装；页面没有凭证或无关配置。**此项不验证本机写入，不切换本机开关或安装、卸载、刷新真实资源。**

### UAT-13 日常使用评价

分别在约 720px 的 Codex 右侧面板与宽窗口查看；可再缩窄到约 390px。请评价查找技能是否方便、按钮是否好找、来源和状态是否易懂、文字是否清楚、排版配色是否现代美观，以及是否愿意用于日常管理。问题请指明页面和操作。

### 可选：Git 来源安装

在演练点击「安装技能」→「Git 仓库」→「填入 Git 演练示例」，子目录和分支留空。预览应为 `git-workflow`，先取消，再重复预览并确认安装，核对来源与记录。使用的是本地 Git 仓库，不需要用户拉取真实私有仓库；此项不替代开发端 Git 导入测试。
