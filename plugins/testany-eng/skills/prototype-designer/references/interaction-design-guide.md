# 交互编排与动效设计指南

Phase 1.3–1.4.2 为 P0 Journey 设计交互时读取；Phase 2 实现直接操控、过渡和组件状态时按需回读；Phase 3 用于真实操作复验。交互的目标是解释状态、空间和因果，不是让页面“多动一点”。

## 先写交互编排，再写动画

对每条 P0 Journey，把关键动作写成一条可观察的链：

> **触发/输入 → 即时反馈 → 进行中变化 → 完成状态 → 恢复/撤销 → 焦点与上下文**

Manifest 的交互编排表至少包含：

| 字段 | 要回答的问题 |
|---|---|
| Trigger / input | 点击、键盘、拖拽、滚动还是系统事件？ |
| Immediate feedback | 用户如何立即知道输入已被接收？ |
| Transition / continuity | 哪个对象变成哪个对象？从哪里来、到哪里去？ |
| Result | 数据、选择、导航或系统状态最终如何变化？ |
| Recovery | 能取消、重试、撤销或返回吗？哪些输入/筛选/滚动位置要保留？ |
| Focus / announcement | 焦点去向、键盘等价操作和动态播报是什么？ |
| Reduced motion | 减少动效时如何保留同样的含义？ |

状态矩阵回答「有哪些状态」，交互编排回答「状态怎样连起来」。两者都必须可演示。

## 六条连续性原则

1. **反馈有来源**：弹层、菜单、卡片或提示尽量从触发点或相关边缘出现；关闭时回到合理来源。无法做空间转场时仍要保持标题、选中项和焦点关系。
2. **同一对象连续变化**：按钮变 loading/success、卡片展开详情、菜单变关闭图标时，尽量保留位置和身份，避免旧对象消失后在别处冒出新对象。
3. **直接操控要跟手**：拖拽/滑动过程中位置与指针连续对应；松手后再依据距离、速度和允许状态决定阈值与吸附。
4. **一条输入驱动一套相关变化**：滚动或拖动可同步位置、亮度、数字和参考线，但它们必须解释同一关系，并共用进度，不各自乱跑。
5. **开始与结束都要完整**：入场、减速、吸附、成功、取消和回收都要说明；突然停住或凭空消失会切断因果。
6. **上下文优先**：能在原处完成的比较、查看和轻量编辑，不强迫跳整页；需要独立 URL、长流程或更大空间时再导航。

## 按输入方式设计

### 点击/触摸

- 按下态与释放态都可感知；常用控件优先短促、克制的形变、色/边界或图标反馈。
- 水波、扩散或展开若用于表达来源，应以真实触点为原点；不必对所有按钮统一加波纹。
- 提交控件可以在原位表达 pending → success/error，但结果需要长期阅读时转到稳定区域，不能让按钮承担全部错误内容。

### 拖拽/滑动

- 定义可拖区域、轴向、边界阻尼、距离阈值、速度阈值、吸附点和取消路径。
- 拖动对象关掉会妨碍跟手的过渡；其余对象可平滑让位。排序先更新槽位/数据模型，不靠绝对坐标伪装。
- 不能只提供指针操作：为排序、数值调整或切换提供键盘/按钮等价方式；触屏命中区域要可操作。

### 滚动

- sticky、缩放、亮度、文案切换等相关变化挂在同一滚动进度上，避免四段互不协调的动画。
- 滚动叙事只用于内容确实存在顺序或空间关系的页面；操作型页面不拦截常规滚动制造“电影感”。
- sticky 元素不得遮挡焦点、锚点和错误提示；窄屏明确取消、折叠或改为普通流。

### Hover / cursor

- hover 用于预览、比较和精细反馈，不承载唯一操作或必要信息。
- 光标形态、磁吸或邻位让位要匹配可点击性，并有 focus/touch 等价状态。
- 避免 `transition: all`；优先只动画 transform、opacity 等必要属性，真实能力以项目栈为准。

### 键盘与系统事件

- 主从列表、标签、菜单、弹窗、拖拽替代操作需要明确键盘模型和焦点返回。
- 自动刷新、筛选联动、上传/保存完成等系统变化用合适的 status/aria-live，避免频繁重复播报。

## 可复用的交互家族

选择能解决当前任务的模式，不为了展示把所有模式塞进一页。

### 1. 原位转换：减少眼睛和上下文移动

| 模式 | 适用 | 编排重点 | 避免 |
|---|---|---|---|
| 搜索图标 → 输入框 | 高频轻量搜索 | 原位展开、自动聚焦、Esc/清空收回 | 跳新页后丢列表上下文 |
| CTA → 步进器 | 添加/数量调整 | 同一位置变形；数量归零恢复 | 两套控件同时出现 |
| 提交按钮 → 状态 | 短提交或生成 | 防重复、pending、结果、失败恢复 | 成功只闪一下且数据未更新 |
| 列表项 → 内联详情 | 快速查看少量信息 | 其他内容自然让位，当前项保持锚点 | 展开后无法折叠或焦点丢失 |
| 卡片 → 详情 | 对象身份很重要 | 共享边界/图片/标题，返回原位 | 仅做视觉特效却没有可靠导航语义 |

### 2. 主从与比较：让多对象保持可见

| 模式 | 适用 | 编排重点 |
|---|---|---|
| 列表 + 详情抽屉 | 快速连续查看记录 | 当前行高亮，列表保留，键盘上下切换，关闭回触发行 |
| 模块就地放大 | 深读一张图表/画布 | 从原格放大，其他模块缩成可发现的切换入口，关闭原路返回 |
| 多图表联动 | 同时间/类别横向比较 | 共用参考线和选中值，其余数据降级；触屏/键盘有锁定方式 |
| 前后对比滑块 | 视觉差异 | 分割线跟手、两侧标签清楚、键盘可调 |

### 3. 全局变化：一处输入，多处可信更新

- 全局筛选放在可发现的稳定位置；切换后相关数字、图表、列表和总数同步更新，不整页闪白。
- 数字滚动、图表插值只用于说明「同一指标变了」，单位、精度和布局宽度保持稳定。
- 加载、空结果与失败要区分；筛选无结果优先保留筛选条件并提供清除入口。
- 多层未读数、角标和列表状态必须同源更新，不能动画完成后数值互相矛盾。

### 4. 覆盖层与抽屉：保留空间关系

- 抽屉从关联边缘进入；半屏高度由「还需看见多少背景上下文」决定，不由固定比例决定。
- 全屏展开时圆角、抓手、位置和内容连续变化，让用户理解还是同一面板。
- 嵌套覆盖层进入时，前一层适度后退/降级；不要无限堆叠。关闭顺序、Esc、遮罩和焦点范围明确。
- 松手后的关闭/展开同时考虑位移和速度，并吸附到合法锚点；中间位置只是过渡，不留下半坏状态。

### 5. 通知与可恢复操作：反馈不抢戏

- 通知从相关区域出现；多条到来时排队或让位，不互相覆盖。
- 可撤销操作同时展示剩余时间的可感知进度，并保持撤销按钮可聚焦。
- 通知消失、角标减少和列表状态改变保持因果同步；错误提示停留到用户有机会理解和处理。
- 不把所有反馈都做 toast：字段错误靠近字段，局部错误留在局部，全页不可用才升级为页面级状态。

### 6. 信息空间与直接操控：位置本身表达含义

- 看板拖拽：其他项让位、目标槽可见、松手吸附；保存失败时回滚并说明。
- 时间轴/泳道：拖动或缩放不破坏时间刻度；冲突、当前时间和空档有非颜色线索。
- 堆栈/轮播：后续内容露出，当前项明确；距离中心可驱动缩放/亮度，但不要妨碍阅读。
- 地图/画布：浮层不遮关键对象；选中、缩放、详情和返回共享同一空间上下文。

## 组件状态要形成系统

为本轮用到的交互组件列适用状态，不机械要求每个组件拥有全部状态：

| 状态 | 需要表达 |
|---|---|
| default / hover / focus-visible / pressed | 可操作性、输入方式和即时反馈；focus 不得只复制 hover 后消失 |
| selected / expanded | 当前选择或空间关系，不能只靠颜色 |
| disabled | 为什么不可操作；不接受事件，仍保持必要可读性 |
| loading | 操作已接收、防重复；布局尽量稳定 |
| success / error | 发生了什么、数据是否更新、下一步或恢复动作 |

图标状态切换优先保持线条/位置连续；一次性反馈可以使用短动画，但只留给高频或高价值动作。骨架高度与最终内容几何接近，避免加载完成跳动。

## 动效预算与节奏

- 每页选择 **1–3 个招牌交互时刻**；其余动效服务反馈、空间和连续性。招牌时刻之间不能同时争抢注意力。
- 先采用项目已有 timing/easing token。没有基线时可把约 `80–160ms` 作为按压/微反馈、`160–240ms` 作为控件状态、`220–360ms` 作为面板、`280–500ms` 作为较大空间转场的调试起点；它们不是验收阈值，按距离、设备和实际观感调整。
- 入场可以轻微错峰，但先出现的是信息层级更高的内容；不要让每个列表项长时间逐一表演。
- 超调/弹簧表达质量、吸附或完成时才使用，幅度小且可中断；危险操作不靠欢快弹跳弱化后果。
- 减少动效时取消大位移、视差、自动循环和弹性，保留即时状态切换、焦点、文本和非动画反馈。
- 不为装饰新增依赖。已有 GSAP、Anime、motion 库时按项目用法清理生命周期；没有时用 CSS/现有能力完成必要表达。

## 实现与验证边界

- 先让功能和状态模型成立，再加过渡；动画结束事件不能成为唯一业务状态来源。
- 直接操控要在低帧率或中途取消时仍能落到合法状态；避免只在理想手势下成立。
- 视觉连续不能破坏语义 URL、浏览器返回、键盘顺序或屏幕阅读器状态。
- 截图只证明某一帧。对每个 P0 编排至少实际执行触发、进行中/等待、完成和一个恢复路径，记录预期与实际。
- 复核三问：用户是否知道输入已被接收？是否理解页面为何这样变化？能否撤回、恢复或继续？任一答案不清楚，交互仍未完成。

## 示例：失败记录工作台

| 动作 | 交互编排 |
|---|---|
| 切换时间范围 | 顶部筛选立即显示选中与 loading；KPI、趋势、列表同源更新且不整页重载；失败保留旧数据与条件并提供重试；焦点留在筛选控件 |
| 悬停/聚焦某日 | 所有图表同步同一日期参考线与值，其余数据降级；键盘左右移动日期；离开后恢复，触屏点击可锁定 |
| 打开失败详情 | 当前行高亮，右侧详情抽屉进入并压窄列表；焦点进入标题/首个操作；上下键切记录；关闭回当前行并保留滚动/筛选 |
| 重试 | 按钮原位进入 pending 并防重复；成功更新该行和汇总数，失败保留详情与原因；可重试，动态结果适度播报 |
