# 页面构成与设计基线提取指南

Phase 0.3.1 使用：从已有系统提取可信的视觉与交互依据，供 Visual Brief 和页面实现引用。

## 取证方式

选择 2-3 个与本轮任务有关的代表页面，读取布局结构、引用的主题/token 与样式；在可运行时观察实际页面并记录视口截图。只读 JSX 可以识别结构，不能证明视觉效果。

| 类别 | 提取内容 | 来源证据 |
|---|---|---|
| 页面骨架 | 导航、内容宽度、侧栏、主次区域及对齐 | 页面/布局文件与实际视图 |
| 排版与颜色 | 字体回退、角色层级、语义颜色、前景/背景配对 | token/主题/字体配置 |
| 间距与密度 | 间距尺度、表格行高、控件尺寸、分组与留白 | 样式定义与代表页 |
| 组件细节 | 圆角、边框、阴影、图标、可用变体 | 主题/Storybook；Props 留待匹配时深读 |
| 页面模式 | 列表/详情/表单布局、主要操作、分组与渐进披露 | 顶层结构与操作观察 |
| 状态与反馈 | 加载/空/错误、成功反馈、输入保留、返回和焦点 | 状态实现与真实操作 |
| 适配与动效 | 断点、重排/滚动、支持主题、动效及减少动效 | 样式和不同视口观察 |

## 记录方式

写入仓库探查报告，不另造文档。每项区分已有事实、缺口与疑似缺陷：

| 维度 | 现有约定/观察 | 来源路径或截图及视口 | 本轮处理 |
|---|---|---|---|
| [排版/布局/状态等] | [具体值、模式或问题] | [文件:行号 / 截图，宽×高] | [继承 / 补齐 / 沙箱内改进 / 待澄清] |

## 分支与边界

- 样本少时只记录有依据的事实，不从一个页面强推全局规则；其余在 Phase 1.4.1 建立最小基线，视觉质量检查照常执行。
- 有有效设计系统时以系统为依据；旧页面的偶发偏差不自动成为规范。无法判断冲突权威时只问影响方向的缺口。
- 已有 UX 缺陷有具体影响时，记录并在沙箱允许范围修正，不因“统一”复制问题；无法修正的生产组件限制交付时明确说明。
- 浏览器不可用时标记仅做了代码取证，不猜测截图和运行结果；不要为探查擅改生产入口。
- 不全量读取组件 Props 或枚举全部 CSS；只记录本轮页面实际需要的设计信息。
