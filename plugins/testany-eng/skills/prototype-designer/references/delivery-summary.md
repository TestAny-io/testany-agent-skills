### 对下游的输入

原型暴露的数据和技术需求。独立使用、暂不进入 API Contract/HLD 时也保留简要记录，供后续开发参考。

**对 API Contract**：
- [原型暴露的数据需求——哪些页面需要什么数据、什么结构]
- [分页/筛选/排序等列表类需求]
- [实时性需求（如需 WebSocket）]

**对 HLD**：
- [状态管理复杂度（跨页面共享状态？）]
- [缓存需求（哪些数据需要缓存？）]
- [性能敏感点（大数据量页面、高频交互）]

### 推荐下一步

1. 团队走查原型，收集交互反馈
2. 基于反馈迭代原型（重新执行 `/testany-eng:prototype-designer`）
3. 执行 `/testany-eng:prototype-reviewer`，按完整证据评审；草稿先列需补项
4. 在 testany 研发流程中：原型准出后进入 `/testany-eng:api-writer`，再按流程进入 HLD；部分/独立模式的原型要进入该流程时，先把需求推断卡补成正式 PRD/Journey
