# BRD 访谈框架

模式与事实标准以 [interview-modes.md](../../../references/interview-modes.md) 为准；具体业务维度见 [问题库](interview-question-bank.md)。不要将参考问题重复变成入口门禁。

## 按证据组织工作

1. 从已有材料提取原始意图、角色、目标、现状、范围、约束和来源。
2. 按用户本次目标选择访谈、整理或缺口补问。只改片段时不执行全流程。
3. 比较来源，找出真正冲突或缺失；先处理会改变范围、验收、优先级或批准依据的缺口。
4. 已有材料充分则直接生成草稿；材料不足但可继续的部分先整理，未决项保持可见。
5. 按事实状态检查交付，不按问了多少题、花了多久或假设数量给准出。

## 问题设计

| 情况 | 方式 |
|---|---|
| 目标或流程未知 | 开放式问题，允许原话描述 |
| 已有可信候选，互斥 | 单选并解释实际取舍 |
| 并列范围或属性可共存 | 多选或文本列表，不误强制单选 |
| 数字未知 | 问可用来源或测量计划，不强迫猜数 |
| 不同来源冲突 | 引用具体差异，只问有效决定的缺口 |

每轮 2-3 个高价值问题是节奏上限，不是必须凑满的数量；用户要求一个问题或阶段检查点时按其要求。工具选项数量和 free-text 能力以当前宿主为准，不要求不可用工具或虚构完整候选集合。

## 分支与材料负载

目标、人群、成功定义、范围、约束、依赖是检查维度而非固定问卷。行业分支只在涉及该行业且缺口相关时读取。合规/医疗等知识作为识别问题的线索，不冒充已经核实的最新规范。

## 假设管理

记录假设内容、来源/依据、置信度、影响、验证方式和负责人（未知明确未知）。
一个影响权限或验收的关键假设可能阻止锁定基线；多个低影响待验证项也不必阻止草稿。不得用“3 个警告、4 个阻塞”等数量阈值替代风险判断。

## 完成

本次访谈到用户指定检查点即可等待；本次材料整理则应实际交付约定文档。资料完整、检查通过和 Owner 批准是不同事实，分别记录。
