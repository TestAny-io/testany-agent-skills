# 持久台账与视图

建立台账或改变结构/统计口径时读取。已有 issue tracker、执行计划或测试矩阵能够保存这些事实时继续使用；以下 JSON 是可选的最小本地格式，不要求迁移、并行维护副本或新增数据库。

## 事实分工

台账是任务身份、关系、原始承诺和进度汇总的 authority；测试记录、Review Record、Owner 决定仍是相应事实的 authority。一个证据可关联多项任务，但不能因此把多项都算通过。只登记适用关系，不复制工程细节或重新签发批准。

记录位置遵循用户/仓库约定。例如仓库已有长期执行计划，优先在其旁边放台账并互相链接；恢复入口只保留一个。跨仓项目选择一处共享可访问位置，在其他仓库放引用，不各养一棵树。上下文里的计划工具可辅助当前回合，不能成为唯一长期记录。

## 可选 JSON 格式

从 `../assets/ledger.json` 复制空模板至实际项目目录，填入真实资料；相对引用以台账目录为基准。字段名固定，标题、原因和回答按用户语言。不要将凭证或完整私人对话拷入台账。

顶层：

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 当前为整数 `1` |
| `project` / `revision` / `as_of` | 项目名称、每次更新递增的记录版本、最后核对时间；未知时间用 `null` |
| `roles` | 用户绑定的角色、宿主/会话身份、授权动作与来源、最近读取位置；缺失身份或授权不能猜 |
| `tasks` | 稳定编号的工作节点，下面给出格式 |
| `collections` | 固定成员集合；原始承诺、新增批次分别建集合 |
| `focus` | 当前推进路径的 ID 数组；相邻节点为直接子项或直接前置依赖 |
| `questions` | 有编号的待答/已答问题；协作格式见 coordination.md |
| `changes` | 简短的变更记录：何时、哪些 ID、什么变化、依据；不存每条命令 |

节点示例（只示范结构，不是实际项目结论）：

```json
{
  "id": "TASK-042",
  "title": "Workspace delete 的拒绝路径测试",
  "parent_id": "TASK-010",
  "depends_on": ["TASK-030"],
  "scope": "accepted",
  "status": "failed",
  "owner": "writer",
  "done_when": "既定拒绝路径用例通过，保留适用版本与结果",
  "source": "exec-plan.md#test-42",
  "evidence": ["results/run-08.md#test-42"],
  "updated_at": "2026-09-28T10:00:00+08:00",
  "notes": "依赖 TASK-030 的必要性见 writer 的对应说明；通过后回到 TASK-010。"
}
```

- `id`、`title`、`scope`、`status`、`owner`、`done_when`、`source` 为非空字符串。未知责任人/标准可以明确写“待确认”，状态随之设为 `needs_confirmation`，不伪造来源。
- `parent_id` 为现存节点 ID 或 `null`；`depends_on` 是去重的现存 ID 数组。保存依赖理由和来源到 `notes` 或原始材料；理由不是由箭头本身证明。
- `scope` 为 `accepted` 或 `proposed`。范围未知按 `proposed` 保存并核实；提出者称“必须做”不等于 Owner 批准范围扩大。范围内已授权的必要拆解沿用对应来源，不逐项索要批准。
- `status` 为 `todo / doing / blocked / failed / needs_confirmation / done / deferred / cancelled`。`failed` 指这项自身的结果未满足标准；一次局部尝试失败不自动使整个目标失败。
- `evidence` 是结果引用数组，`updated_at` 为核对时间字符串或 `null`。`done` 必须有完成依据，`cancelled/deferred` 必须有相应有权决定；工具只检查引用存在，不能证明其内容与权限。
- 保留未满足条件的最后结果。回归、撤回或适用版本改变时重新打开相关项并记变更，不能因历史上曾通过仍算完成。

集合示例：

```json
{"id":"TESTS-ORIGINAL","title":"首次承诺的 27 项测试","task_ids":["TASK-042","TASK-043"],"source":"original-list.md","created_at":"2026-09-28T09:00:00+08:00"}
```

示例仅列两项。真实“27 项”必须有 27 个原始成员，不能靠标题充数。后续拆解、新增、取消都不改这个历史集合的成员；使用新集合表示追加批次或新的工作范围。删除/合并任务时保留旧 ID、去向和决定，避免丢失历史计数。父子不能混作同一粒度的完成百分比；若原始清单本身混合粒度，说明原始统计单位并澄清，不偷偷重算。

## 图与完成关系

- 每项单一父节点形成目标森林；依赖允许跨树共享。组合图的等待方向是“父项等待必要子项、依赖方等待前置项”。检查组合图的环，而不只分别检查两类关系；子项依赖自己的未完成父项也会造成循环。
- `proposed` 子项不自动成为已承诺父项的新完成门槛。若它确是无法绕开的前置条件，保存依赖/缺口并向相应 Owner 求证，不能凭它已经做完认定授权已补齐。
- `cancelled` 子项有取消依据后可以不参与原父项的剩余工作；`deferred` 仍是未完成承诺，不当成通过。取消前置项不会自动满足依赖；要按决定删除/替换那条依赖并留变更。
- 父项不因所有子项完成而自动 `done`；秘书核对父项原有标准的结果引用。父项声称 `done` 却有必要子项/前置未完成或前置范围未确认，标出冲突并暂停该完成声明。
- 前置完成只意味着一项已知阻塞可能消除；还可能有别的阻塞。向负责人确认可恢复的具体工作，不自动派发技术执行。

## 只读工具

所有脚本路径从实际加载的 skill 目录解析；参数必须用真实路径并保留引号：

```sh
python3 <skill-dir>/scripts/ledger.py check <ledger.json>
python3 <skill-dir>/scripts/ledger.py status <ledger.json> --collection TESTS-ORIGINAL --pending-only
python3 <skill-dir>/scripts/ledger.py status <ledger.json> --focus TASK-042 --limit 10
```

只用 Python 标准库，只读台账，不跟随证据链接、不联系角色、不改状态或证明批准。结构错误退出 `2`；状态冲突仍输出已知情况与 `needs_confirmation`，不能把退出 `0` 解读为交付完成。返回 `revision/as_of`、明确统计单位、固定集合计数和有上限的明细；`--offset` 可继续读取同一记录版本的下一段。默认最多 12 项，不反复打印全量 JSON。

统计仅计 `accepted`：`done`、活跃剩余（todo/doing/blocked/failed/needs_confirmation）、deferred、cancelled 四部分相加等于已承诺总数；`proposed` 另列。活跃剩余不等于“未执行”，历史已执行但失败的也在其中。未指定集合时显示各集合摘要与顶层目标，绝不把所有层级节点相加伪装成总任务量。单个目标的子项统计使用它的直接子项，依赖列表另列。

工具对记录中的完成矛盾保守计算有效状态，不覆写原记录。结构/引用格式通过不代表事实新鲜、依赖必要性或来源可信；这些由秘书按责任人的材料核实。

## 更新和展示

维护者默认是秘书，Writer/Reviewer 提供既有结果引用。先读当前 `revision` 再局部编辑，发现并发修改先合并；有工具支持时原子保存，不能覆盖新事件。变更日志可只存 `at/task_ids/change/source`，不重写整个历史。一次结果多次到达时按来源版本去重；同一任务晚到的旧版本不压过新版本，也不只按接收时间选结论。

概览默认折叠到主要成果，突出受阻路径和用户决策；路径视图区分组成/依赖并显示未完成同级项；明细按指定集合/分支展开。不要同时生成三份完整报告。无可靠工作量估算时给数量和状态，不声称完成了某个百分比、ETA 或“关键路径”；依赖链不自动等于有工期依据的关键路径。

清单恢复不全时保留已找到项，标出来源覆盖和待找部分；不能把当前搜索结果改称原始完整清单。跨 session 接手只需台账入口、角色绑定、当前路径和未答问题，按索引读取原始证据。
