# 组件选择与组合指南

选择或设计组件时按命中的组件类型读取，组合代表页时回读。组件在每页构图确定之后选：构图决定这里是卡片、列表、表格、抽屉还是看板，组件库决定用哪个实现。本文不授权修改生产组件；优先使用已有公开 Props、变体和组合能力，缺口才在沙箱新增组件（ui-designer 标 `[DESIGN]`、prototype-designer 标 `[PROTOTYPE]`，见 [前端仓库与原型沙箱](../frontend-sandbox.md#4-沙箱目录与隔离规则)）。

## 先定义角色，不先挑外观

为每个关键组件回答六件事：

1. **任务角色**：导航、选择、输入、比较、查看、确认还是反馈。
2. **信息层级**：它承载主任务、次任务还是辅助信息；同组谁先被看到。
3. **内容解剖**：必须字段、可选字段、长短边界、单位和可信文案。
4. **适用状态**：default、hover、focus-visible、pressed、selected、expanded、disabled、loading、success、error 中哪些真实存在；记录在设计记录的组件清单中（ui-designer 的设计语言、prototype-designer 的 Manifest）。
5. **密度与适配**：高频/低频、桌面/触屏、窄屏折叠与最小命中区域。
6. **连续性**：触发后在原位变化、展开邻近内容、打开覆盖层还是导航；如何返回与恢复焦点。

如果只能描述「白色圆角卡片」「蓝色按钮」，说明还没有完成组件设计。

## 导航与页面壳

| 模式 | 适用 | 组合重点 | 风险 |
|---|---|---|---|
| 顶部导航 | 层级浅、横向入口少、展示/内容页 | 品牌、主入口、页面级动作分区；当前项清楚 | 入口过多后拥挤，移动端不可直接照搬 |
| 单侧栏 | 高频桌面工具、模块稳定 | 当前项、分组、底部账户/用量；中段可独立滚动 | 图标与文字都抢、分组全靠分割线 |
| 图标轨 + 二级栏 | 模块与页面两级都多 | 窄轨切模块，二级栏列当前模块；焦点和折叠状态明确 | 用户不懂纯图标、二级栏长期占宽 |
| 可折叠侧栏 | 空间紧张但入口仍需常驻 | 展开/收起有明确控件；文字与宽度协调变化 | hover-only 展开、内容区反复跳动 |
| 浮动/岛式导航 | 表达型、轻量工具或有背景画布 | 与页面材质同源，外边距和层级清楚 | 为“高级感”套大圆角，浪费操作空间 |
| 底部导航/操作栏 | 移动端 3–5 个一级入口或高频动作 | 主操作进入拇指舒适区；安全区、键盘弹出与滚动处理 | 把大量入口硬塞进去、与浮动 CTA 重叠 |

导航的视觉形态可变，信息架构不可随风格随机变化。侧栏深色、玻璃或悬浮只有与整体方向和背景层级一致时才使用。

## 行动与按钮

- 每个操作组通常只有一个主要动作；次要、幽灵、文字和破坏性动作按后果与频率降级，不让所有按钮都实心高亮。
- 图标按钮只用于图标含义稳定且有可访问名称的场景；陌生或高风险动作保留文字。
- 加载时保持尺寸与位置稳定并防重复；成功/失败可原位反馈，但详细错误和后续步骤放在更稳定的区域。
- 按钮变步进器、加号展开面板、菜单图标变关闭等形态转换，只有在对象身份连续且能减少操作路径时采用。
- 危险动作按可恢复性选择撤销、二次确认、长按/滑动确认；不把每次保存都变成仪式，也不靠花哨动效淡化风险。

## 卡片、列表、表格与集合

| 组件 | 优先使用场景 | 设计重点 |
|---|---|---|
| 卡片 | 对象相对独立、需要浏览或带图像/多种操作 | 卡片边界有信息含义；大小可按权重变化，不默认三等分 |
| 列表 | 同构对象纵向扫描、操作简单 | 对齐、行间层级、长文本与状态；详情可内联或主从展开 |
| 表格 | 多对象按列比较、排序、筛选 | 数字/单位对齐、列优先级、sticky/横向滚动可发现、行操作不挤 |
| 网格/画廊 | 视觉对象探索或分类浏览 | 图片比例、焦点顺序、加载占位、选择状态；触屏替代 hover |
| 堆栈/轮播 | 顺序、有限集合或当前项聚焦 | 后项露出、当前位置、拖拽/按钮/键盘切换和自然收尾 |
| 看板/泳道 | 状态/时间位置本身编码业务 | 列/轨标签、数量、拖拽目标、冲突与横向适配 |

- 同一页可混用，但必须有一个主呈现方式。不要把表格每行再包卡、卡里再包卡。
- 同构比较需要稳定对齐；探索性内容可以结构化非对称。选择依据是任务，不是哪个更“高级”。
- 列表 ↔ 网格切换时，同一批对象保持身份和位置连续；筛选需区分离场、让位和新进入对象。做法见交互指南的「实现手法」。
- 高密度页面优先用对齐、细线和留白组织同构信息，不一格一卡；卡片留给相对独立、需要整体操作的对象。
- 真实图片作为主角时，界面颜色和装饰退后；图片质量不可控时不要把整页气质完全押在素材上。

## 表单、筛选与设置

- 按用户思考顺序和业务关系分组，字段标签持续可见；placeholder 不代替 label。
- 高频筛选靠近结果并保留条件；全局筛选只出现一处，清除、无结果、加载和失败明确区分。
- 即时校验用于能明确判断的局部错误；提交后错误把焦点/摘要带到问题处，保留正确输入。
- 高级选项、低频说明和依赖字段渐进披露；隐藏后清空还是保留值必须与 Journey/业务规则一致。
- 多步流程显示当前位置、已完成内容和退出后果；不要把一个短表单无意义拆成向导，也不要把长流程塞进单个模态框。

## 覆盖层怎么选

| 组件 | 何时使用 | 上下文与交互要求 |
|---|---|---|
| Popover / 菜单 | 与触发器紧密相关的短选择或操作 | 锚定触发器、点外/Escape、键盘导航、空间不足时换向 |
| Dialog | 必须先处理的短任务、重要决定 | 焦点进入/循环/返回；标题与动作明确；不装长详情 |
| Drawer / Sheet | 需要保留背景上下文的详情、筛选或编辑 | 从关联边缘进入，可拖时定义锚点/阈值；列表/画布仍可辨认 |
| Inline expansion | 少量详情、轻量编辑、连续扫描 | 当前对象保持位置，邻项自然让位，收起后焦点回触发点 |
| 独立页面 | 可链接、长内容、多步骤或需要更大工作区 | URL/返回成立，保留来源、筛选、滚动和未提交内容策略 |

不要用一个白色居中框解决所有覆盖需求。选择取决于任务长度、是否阻塞、需要保留多少上下文和是否需要可分享 URL。

## 数据、图表与指标

- KPI 只突出决策所需的少数指标；主指标、次指标和状态提示有明确权重，不让五张指标卡同声喊叫。
- 图表类型由比较任务决定；颜色、线型、标签和参考线承担语义，装饰性渐变不能降低读数。
- 多图比较可用同日期/类别联动高亮、共用参考线或锁定选择；触屏/键盘提供等价方式。
- 全局筛选后，数字、单位、图表、列表和总数同步；过渡用于表明数据仍是同一指标，不遮掩 loading/error。
- 无数据、筛选无结果、权限不足和加载失败是不同状态；空态提供与原因匹配的下一步。

## 反馈与系统状态

- **Skeleton**：几何接近最终内容，加载完成不把页面顶来顶去；未知结构时宁可用稳定进度/占位，不伪造精确骨架。
- **Inline feedback**：字段、局部操作或单个模块的问题留在相关位置。
- **Toast/notification**：短暂、非阻塞的确认；多条有队列/让位，错误停留足够久并可操作。
- **Banner**：影响页面范围的持续状态；出现时不遮挡内容和 sticky 区域。
- **Empty state**：说明为何为空，并按首次使用、筛选无结果、清空完成或权限限制给不同下一步。
- **Badge/count**：数字变化保持宽度和多层计数同步；不要让装饰动效抢过信息本身。

## 视觉一致不是组件同质

- 用有限 token 统一字体角色、色彩角色、间距、圆角、边界、阴影、图标线宽和动效语气。
- 角色不同可以有不同形态：输入、卡片、浮层和标签不必共享同一个圆角；主次组件也不必共享同一阴影。
- 一致性检查问「相同语义是否相同」，不是「所有东西是否看起来一样」。页面可用不同构图表达不同任务，只要视觉语言与行为规则同源。
- 组件示例页或 Storybook 只能证明变体存在；必须在真实页面内容、相邻组件、状态和视口里判断组合质量。

## 组件级复核

在代表页上逐个检查关键组件：

- 它为什么是这个组件，而不是表格/列表/抽屉/页面等替代方案？
- 内容长度、零值、错误、权限和 loading 是否破坏尺寸或层级？
- default、focus-visible、pressed、selected/expanded、disabled、loading 等适用状态是否同等完成？
- 鼠标、键盘、触屏与减少动效是否都能完成任务？
- 与相邻组件放在一起时，主次是否仍成立，是否出现圆角/阴影/强调色泛滥？
- 触发后用户是否知道从哪来、发生了什么、如何返回或恢复？
