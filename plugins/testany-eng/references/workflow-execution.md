# 工作流执行约定

适用于本 plugin 的写作、访谈和评审入口；专业门禁仍由各 skill 定义。

## 先取证，再提问

- 先读取用户指定材料与任务直接相关的本地证据，再按需发现补充材料。无需为已获访问范围内的只读操作逐文件索要许可；不扫描整个磁盘或无关仓库。
- 复用当前请求和有效记录中已明确的路径、版本、语言、格式、模式及批准范围，不把阶段切换变成重复确认。
- 读取、文件名、`approved` 标签和文件时间都不单独构成批准。记录批准来源、对象与范围；遇到冲突，先读冲突双方并引用具体差异，仅询问证据无法消除的权威或决策缺口。不得自行选边。
- 模板里的问题是未知项清单，不是必须逐项问答的脚本。一般缺口标记待确认并继续不依赖它的草稿或检查；影响范围、安全或正式准出的缺口不得猜测通过。

## 按实际能力执行

- `Glob`、`Read`、`TodoWrite`、`AskUserQuestion`、`Task` 等是能力示例，不要求宿主有这些名称。使用当前可用的搜索、读取、计划、提问和委派接口；没有计划工具可用简短清单，没有提问工具可用普通文本。批准流程仍服从宿主和用户约束。
- 只有实际存在并获准使用独立 agent 时才委派。没有委派能力时，可顺序写作和分维度自检；这不构成独立评审，不得伪造 agent、工具执行或批准结果。
- 独立评审属于必要准出条件时，无委派能力仍可交付草稿和自检证据，正式准出保持待补。生成命令、写文档、配置完成均不等于命令已执行、部署成功或发布获准。

## 从安装位置定位资源

skill 自带资源相对于**本次实际加载的 SKILL.md 绝对路径**解析，不相对于产品工作目录。先从宿主提供的加载路径确定 skill 目录；`skills/<name>/` 的上两级是本 plugin 根目录，再核实所需脚本存在。

本文及命令示例中的 `TESTANY_ENG_ROOT` 是读取实际路径后自行设置的本地 shell 变量，**不是宿主保证提供的环境变量**。例如实际加载路径为 `/installed/testany-eng/skills/prd-writer/SKILL.md`，则设置为 `/installed/testany-eng`；勿复制此示例假路径。后续调用形式：

```bash
python3 "$TESTANY_ENG_ROOT/scripts/trace_lint.py" --format json /absolute/path/to/artifact.md
```

产品工件参数使用用户指定工作区的实际路径。保持路径引号，支持空格目录。无法获知加载位置或脚本确实缺失时，报告确切未执行项及影响；不去产品仓库猜 `plugins/...`，不全盘搜同名脚本代替权威资源，不声称 lint 通过。Code Reviewer 的脚本源、digest 与批准对象规则仍按其专用协议执行。
