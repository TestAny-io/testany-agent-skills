# 交付与读回验证

用于本地 case package、case/pipeline/trigger/workspace 变更。目标是让完成声明对应真实证据，不将静态检查升级为未授权的平台执行。

## 分层状态

| 状态 | 证据 | 不能据此声称 |
|---|---|---|
| 本地已生成 | 文件路径、实际内容 | 可注册、已上传、已实测 |
| 本地静态检查通过 | 归档/入口/metadata/可用语法检查的实际结果 | 平台 runtime、依赖、权限、凭证可用或执行成功 |
| 远程请求已受理 | API 返回及真实对象/request key | 配置已生效、资源已批准可用 |
| 配置读回一致 | get/list 实际状态与本轮预期变更一致 | 测试已运行或成功 |
| 执行已提交 / 已终态 | 真实 execution key / 终态查询 | 其他环境、版本或未来执行同样成功 |

本地生成完成与本地可注册准备完成分开。必要检查未做、入口缺失或配置不一致，不能用“可直接上传/可运行”笼统带过。

## 本地包最小检查

生成/接收 ZIP 后、创建可运行对象或上传前，核验：

1. ZIP 可读、成员可读取/CRC 正常，路径无越界、绝对路径或危险 symlink；不要解压或执行未经验证内容。
2. 归档根布局与选定 executor 一致；metadata 声明的文件/目录入口确实存在；command 型入口仅静态检查，不能执行 command 来“验证”。
3. name/description、executor、入口、必要依赖声明，以及环境变量类型/唯一名称/non-empty value/secret_ref 是否一致。secrets 不带明文 value 或只读 status；缺少实际引用可保留待配置，但不能认定注册就绪。
4. 运行当前已有的无副作用检查，例如 Python AST、JSON 解析、已有 lint。缺少语法工具/依赖时明确检查缺口，不自动安装，不运行测试脚本、构建生命周期脚本或网络请求。
5. 结果对应最终 ZIP 和 metadata，不验证旧文件后再换包；修复后重新检查。保留每个 case 的结果和实际交付路径。

可用 [本地校验器](../../testany-case-writing/scripts/validate_package.py) 对 JSON metadata 和 ZIP 做离线检查。它不完整实现平台 schema，不证明依赖可安装或目标 runtime 一致。YAML 或不能识别的命令型入口应使用已有安全解析器或人工检查，并标明未验证部分，不把校验器能力缺口当平台缺陷。

## 平台变更

- 更新前 get 当前状态，只修改用户指定字段；整集合替换字段先合并现有内容，不覆盖未请求项。
- 创建/更新后用真实 key read-after-write：case 配置与脚本上传状态；pipeline 配置/YAML、引用 case、relay；trigger 绑定与启用状态；workspace 申请、实际成员/角色。只读取与当前变更相关的内容，不需全租户扫描。
- API accepted/HTTP 200 是请求证据，不替代最终状态。无读取能力、读回不一致或服务仍待生效时，分别报告未验证/不一致/待生效；不得无限轮询或自动重写。后续等待/重试只在用户目标及许可内。
- 申请 workspace 已受理不等于 workspace 已批准可用；权限变更请求成功不等于实际角色已生效。
- dry-run、pipeline run、外部 webhook 调用都是执行动作，严格按 [执行授权](execution-boundaries.md)；不能作为默认只读验证。

## 部分失败

记录每项已有对象 key、请求/读回状态、剩余项及失败原因。对象已创建但上传失败，保留对象，不重建、不自动删除“回滚”；无响应无法确认写入时先只读核实，不能盲目再次创建。仅当用户授权的目标和重试/删除范围明确时才做相应后续动作。

完成报告匹配 [整体目标](task-handoff.md)，不以局部成功掩盖未完成，也不因正常缺口否认真实已完成部分。
