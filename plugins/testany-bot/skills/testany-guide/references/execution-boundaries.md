# 配置、执行与等待的边界

供 case、trigger、execution 在发起执行或等待结果时使用；不增加平台字段或重命名状态。

## 执行许可

配置、上传、注册、读取状态与执行测试是不同操作。补齐必填字段不自动授权 dry run；
dry run 会执行脚本，不能以名称判断无副作用。发起前核对本轮任务是否包含执行，以及精确
case/pipeline、runtime、环境、版本、凭证用途和可能的写入/计费影响是否在授权内。
能从请求与已有资料确认就直接使用，不重复询问；关键目标或副作用不明只问缺口。

用户明确授权一次隔离验证且目标和影响已知时，可配置后连续执行一次并读结果。
只要求配置则交付配置和「未执行」；只查已存在执行则查询该 key，不能新开验证。
失败不自动授权重试、取消、切 runtime、改环境或运行 pipeline；这些动作另看当前授权。

## 等待合同

| 用户目标 | 行为与停止点 |
|---|---|
| 查询当前状态 | 一次必要查询后交付；不因 RUNNING 自动长轮询，也不自动 refresh |
| 只发起一次 | 返回真实 key 和发起结果；不把已发起说成成功 |
| 明确等待结果 | 首次查询前记录开始时间和截止时间，按剩余预算有界观察 |

用户给定的更短预算优先；未指定时默认总等待 10 分钟，不因 pipeline 复杂而自行延长。
计时必须来自实际时钟：首次查询前保存 `started_at` 和 `deadline = started_at + budget`，
每次调用前重新取时钟计算剩余量；只说“会在预算内等待”不算记录。可用同一脚本内的
monotonic 时钟，或跨工具调用可保留的时间值；计时保留亚秒精度，不用整数 `SECONDS` 或
逐次向下取整的耗时补算预算。只有低精度时钟时保守扣除不确定量，不能据此延长等待。
不要求另造交付文件；观察期间的工具、调度和对话耗时均计入预算，结束后的结果说明不属于继续观察。
例如同一 Python 观察脚本先执行 `started_at = time.monotonic(); deadline = started_at + budget_seconds`；
包括首查在内，每次操作前重新计算 `remaining = deadline - time.monotonic()`，只有 `remaining > 0`
才发起操作，查询 timeout（若支持）与 sleep 不超过 remaining。打印起止时间后无条件查询不算预算控制。
这是计时示意，工具调用仍用当前真实接口，不能用示例值冒充实际时间、key 或结果。
首次查询后若仍为 -1/0，间隔从 5 秒退避至最多 30 秒；等待不超过剩余预算。
按当前工具的实际响应结构解包状态，不猜测状态一定在顶层或 data 内。临时观察代码无法
解析时停止并明确报告本地解析失败；不能将缺失字段当终态、预算耗尽或远程失败。
每次查询/refresh/睡眠前检查截止时间，API 耗时也计入预算。预算短于下一间隔时可在预算内
等待至截止并结束，不需要为凑次数再查。工具支持 timeout 时限制到剩余预算；不支持时披露
单次工具调用无法强制中断，不能据此继续循环。
间隔等待使用可用的 sleep/定时等待，不用空循环反复读时钟占用 CPU；醒来后再检查剩余预算。

任一 get 或 refresh 已返回已知终态，就用该响应结束本次等待；不为“再确认一次”追加同对象
get/refresh。本次请求已包含或后续新增的详情、日志、排障目标，按其原有授权继续，不为结束
等待而要求重复批准。未知状态报告无法判定，
不用 `>=1` 推断成功。遇工具错误停止并披露
观测失败，不忙重试。用户中断时停止新调用；不要把当前线程停止或等待到期说成远程已取消。
取消、重试、追加等待预算不从原等待目标自动继承。

交付：对象 key、最后观察的实际状态和时间/覆盖限制、本次是否发起、是否已到终态、是否
因预算/工具问题停止。只有终态证据可以支持成功/失败/取消结论。状态数字保留平台语义。
