# 整体目标与 Skill 交接

本约定用于跨 skill 的已授权任务，不把职责分工变成对话停止点，也不把自动衔接变成扩大授权。

## 先确定本次终点

- 只问概念或下一步：解释/导航即可，不操作对象。
- 只要本地包、注册、配置或当前状态：完成指定部分即止，不自动执行、等待或进入其他工作流。
- 明确要求注册后编排、执行一次并等结果等完整目标：保留整体目标，按需读取下一 skill 的 `SKILL.md` 并在当前对话继续。已有授权覆盖的交接不重复索取授权，不只留下命令建议。
- 需要扩展目标、触及未授权环境/凭证/副作用或出现真实缺口：停在该边界，说明已完成部分及最小待决事项。用户明确要求逐阶段确认时遵循该节奏。

## 交接携带的信息

复用对话和实际产物即可，无须为每次交接另造表格或 JSON 文件：

1. 用户原始目标与停止条件，允许的动作、目标 workspace/环境、次数及明确禁止项。
2. 有来源的输入和方案：Test Spec/批准状态、scenario 与 case 对应、executor/runtime、依赖、relay、分支、visibility。
3. 已存在的本地绝对路径、真实平台 key 与本次已提交动作。每次调用前将目标 key 对照用户明确指定的现有对象或本次工具实际返回值；新建对象只能使用创建响应返回的 key，文档/工具示例 key 不是任务对象，连只读查询也不能直接代入。响应未给出 key 时按实际能力查询定位或报告缺口，不猜 key、重建对象或把计划写成完成。
4. 实际验证结果和限制：本地静态检查、远程配置读回、执行提交与执行终态分开；携带未完成项及失败原因。
5. 下一步只接续未完成的目标；失败后保留已有资源，不自行扩大为排障、重试、删除或回滚。

新建对象与依赖其 key 的调用不能作为互不依赖的并行操作，也不能预先用示例 key 串接；先解析实际创建响应并确认 key，再提交后续请求。只读操作同样遵守这一依赖。

## 典型接续

| 当前产物/需求 | 下一职责 | 何时继续 |
|---|---|---|
| 仅有场景，需要生成包 | `testany-case-writing` | 用户要本地材料或完整自动化落地 |
| 已验证本地包，需要平台对象 | `testany-case` | 目标含注册/更新/上传 |
| 已注册 case，需要执行编排 | `testany-pipeline` | 目标含创建/更新 pipeline |
| 需要持久入口或立即执行一次 | `testany-trigger` | 目标明确要求相应入口或一次执行；二者不能互相替代 |
| 已返回 execution key | `testany-execution` | 目标要求查询或等终态；仅启动一次则报告已提交即可 |
| 失败执行需要根因调查 | `testany-debug` | 用户目标包含排障，而不只是报告失败状态 |

授权与等待预算以 [execution-boundaries.md](execution-boundaries.md) 为准：配置许可不是执行许可，等待不是重试许可；跨 skill 接续必须沿用已开始的同一等待期限，不重置计时。缺少 slash/router 时读取本次安装位置的相邻 skill 继续；缺少实际操作能力时报告能力缺口，不伪造执行、安装工具或让用户重复已经提供的业务信息。

完整链路也不能跳过等待初始化：执行已发起且目标包含等结果时，在首次状态查询前用实际
时钟保存开始值和截止值，再查询；不能等看到 RUNNING 才补记。get/refresh 一旦返回终态
直接用于结案，不为完成交接再查一次。同一脚本可连续处理交接，无须向用户新增确认。

## 完成判定

以**用户本次目标**而非当前 skill 的局部输出判定完成。配置已验证但执行仍运行中，只能报告执行尚未完成；上传失败但 case 已创建，必须返回其 key 和剩余工作。已到明确停止点时不为了显得完整而追加工作流。
