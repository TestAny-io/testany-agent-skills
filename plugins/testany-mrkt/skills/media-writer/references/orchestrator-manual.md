# Orchestrator - 工作流执行手册

先读取本次安装的 `../SKILL.md` 与 [写作执行与授权约定](execution-modes.md)。本文管理阶段操作，专业写法仍由 `prompts/`、`platforms/`、`persona/` 提供；不依赖 cwd 下假定存在的 CLAUDE/copilot 文件。

## 启动与状态

读取用户给定材料后记录：模式、主题、受众、立场、平台、输出路径、已满足输入、实际检查点、事实缺口和副作用边界。已有答案直接复用；只对缺失且影响任务的选择提问。

`end_to_end` 连续完成必要步骤；`checkpointed` 只在指定点停；`single_stage` 仅完成指定步骤。八阶段是能力目录，不是强制八次审批。允许复用既有素材、修改已有稿件及跳过不适用的阶段，不能跳过实际需要的事实核验或越过用户检查点。

本手册中的 `prompts/`、`platforms/`、`persona/` 相对本文件目录；模板在 `../assets/`，脚本在 `../scripts/`。工作产物路径相对用户工作区，用户指定路径优先于下列默认命名。历史文章仅在实际存在且获准读取时使用。

## 通用阶段操作

1. 检查本阶段所需内容是否已在给定材料中满足，不仅判断某个默认文件名是否存在。缺真实输入时列出精确缺口；继续不依赖该缺口的工作。
2. 读取对应 prompt 及必要素材。工具名是能力示例，实际使用可用且获准的读取、检索、任务追踪工具。
3. 在已授权范围执行；不得伪造作者经历、数据来源、检索或独立 agent。多平台可顺序或在获准能力下并行。
4. 将实际需要保存的产物写到约定路径，并读取检查内容。无须为每个内部步骤复制同一稿件；检查点或需要恢复工作时保留中间产物。
5. 向协调者返回产物、检查和缺口。协调者按模式继续、结束或等待，不把被委派者返回等同于人工审批。

## Stage 1：主题与 Brief

读取 `prompts/01-topic-scout.md`。有完整 Brief 则校验并复用；有主题则补齐受众、核心信息、角度和素材需求；没有主题且请求找热点时，在实际可用且获准的检索范围搜集并标注来源。不能离线声称发现今天热点。

需要用户决定的新主题或实质立场时给出有依据的选择；主题与平台已明确则不重问。Brief 可保存为 `workflow/01-briefs/{topic}-{date}-brief.md`，检查点请求必须保存并停在此处，不提前做研究或写正文。

## Stage 2：素材收集

读取 `prompts/02-researcher.md` 与 Brief。限定本地素材时只整理、核对给定来源；获准联网时按论点检索官方资料、可靠报道、案例和相反证据。

检查实际使用的断言是否有支持，数值是否有时间、口径/样本和来源。素材数量不代替覆盖判断，不要求短观点稿满足研究报告的数据配额。无来源数字或业绩留待确认，不生成虚假引用，也不无限检索阻断不依赖它的段落。

需要独立素材工件时保存 `workflow/02-materials/{topic}-{date}-materials.md`，包含事实、观点、出处、局限和缺口，不虚称全面覆盖全部观点。

## Stage 3：角度与平台策略

读取 `prompts/03-strategist.md`、Brief、素材和作者材料。用户已指定角度直接展开；明确授权自主选择时给出选择理由。只有需要用户作实质新决定时询问。

需要探索角度时分析若干可行选择，记录核心观点、优劣、适配平台、提纲和风险；参考 `../assets/angle-analysis-template.md`。独立产物可保存 `workflow/03-angles/{topic}-{date}-angles.md`。已确定平台不再重新选择。

## Stage 4：平台草稿

读取 `prompts/04-writer-{platform}.md`、`platforms/{platform}-guide.md`、获准素材及作者风格。核对数量、平台、角度和输出位置；都明确时直接写，不增加“确认开始”问题。

每个目标平台分别适配开头、结构、论证深度和结尾。用户明确字数优先于通用平台长文范围。用 `../assets/draft-checklist.md` 中适用项自检，不将虚构的第一人称经历或数据写成真实事实。

多平台有真实且获准的委派能力时可独立分派，否则顺序完成。默认路径为 `workflow/04-drafts/{platform}-{topic}-{date}-draft.md`；用户指定路径优先。报告真实执行方式，不声称固定倍数加速。

## Stage 5：候选稿筛选

读取 `prompts/05-selector.md`、当前任务范围的草稿、作者价值观及受众材料。比较论据、主题、平台适配和表达，按平台选出候选并说明理由、问题与改进建议。

只有一篇且已选定可直接进入必要编辑，不人为再造草稿。需要筛选工件时保存候选稿及 `workflow/05-candidates/selection-report-{date}.md`，不修改无关文章。

## Stage 6：编辑

完整成稿按逻辑→风格→细节检查；仅请求单一维度时只做该项。

| 维度 | Prompt | 检查内容 |
|------|--------|----------|
| 逻辑 | `prompts/06-logic-editor.md` | 事实与引用、数字口径、论据和结论、反例、逻辑漏洞 |
| 风格 | `prompts/06-style-editor.md` | 作者语气、节奏、平台表达；不以添加虚构亲历强化人设 |
| 细节 | `prompts/06-detail-editor.md` | 字数、标点、排版、段落、拼写、最终通读 |

有修改授权时修正并保留必要变更说明；只读审校不擅自改稿。缺事实的相关段落保留明确待确认项，继续其他编辑。三维度自检不等于三名独立审查者，也不要求三次人工审批。

保存最终交付路径并实际读取验证；默认可用 `workflow/06-finals/{platform}-{topic}-{date}-final.md`。如有未确认的关键事实，状态为“含待确认项草稿”，不声称可直接发布。

## Stage 7：配图（仅请求包含时）

读取 `prompts/07-illustrator.md` 与成稿，确定配图位置、用途、风格和替代文本。获准检索时检查图片来源与使用限制；无法取得合适素材时可交付生成 prompt，但不把 prompt 当成已生成图片。

付费生成、外部上传和发布都须满足实际授权范围。默认图文稿 `workflow/07-illustrated/{platform}-{topic}-{date}-illustrated.md` 需核对每个位置与真实素材状态。仅完成方案时如实称“配图方案”，不宣布所有发布材料齐备。

## Stage 8：归档（仅请求包含时）

读取 `prompts/08-archivist.md`。先界定具体项目、实际交付文件、目标目录以及复制或移动方式；无配图的纯文本项目可归档，不强制补齐八阶段。

归档仅操作已确认属于本项目的清单。不得通配清空整个 workflow、覆盖既有归档或移动其他项目文件。用户只要求备份时复制，不擅自删除原文件；“归档”未明确移动含义且会移除用户文件时先明确该范围。

可使用 `archive/{YYYY-MM}/{project}/`，只创建必要目录。生成 `project-summary.md` 列出原路径、归档路径、复制/移动方式、事实缺口与项目状态；核对内容和清单，报告实际移动或复制数量，未执行项记明。

归档不等于发布或启动新项目。只在归档验证成功后更新本项目工作状态，不重置无关任务。

## 继续、重做与快捷命令

- “继续”“可以”结合最近明确提案解释，仅推进已获准范围；遇到检查点仍按约定停。泛泛称赞不新增授权。
- `/new`、`/draft`、`/review`、`/illustrate`、`/archive` 指定对应能力；按上下文判断单阶段还是已授权连续流程的入口，不自动加载全部八阶段。
- 用户指定重做某项时处理该项并评估下游影响；不默认重做所有产物。实质新增作者立场或副作用才需补充明确决定。
- `/status` 仅报告真实已完成、正在做、待确认与不适用项，不假造完成状态。

## 完成与错误处理

报告模式、实际文件、主要检查、事实缺口和未执行项。只有检查点请求才报告“停在指定检查点”；端到端完成后直接交付，不追加下一阶段审批问题。

写入失败或工具失败先查明原因，最多一次有依据重试；仍失败说明阻碍，保留已完成结果。必要工具不可用不虚称通过，能够以现有能力完成的独立工作继续。

最后确认：没有越过检查点，没有捏造数据或独立执行，没有执行未获准的发布/付费/归档，没有把文件存在当成内容合格。
