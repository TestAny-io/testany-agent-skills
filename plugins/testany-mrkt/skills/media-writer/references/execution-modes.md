# 写作执行与授权约定

本约定由 SKILL、执行手册及各阶段 prompt 共同引用，管理阶段推进；平台写作和事实质量要求仍适用。

## 三种模式

| 模式 | 判定依据 | 执行终点 |
|------|----------|----------|
| `end_to_end` | 用户要求写完文章、连续完成或完成必要润色 | 连续完成已授权的必要工作并交付，不在内部阶段重复索要批准 |
| `checkpointed` | 用户明确要求逐阶段确认，或指定某个检查点 | 仅在指定检查点停下；“逐阶段”才表示每阶段都停 |
| `single_stage` | 用户仅要求 Brief、角度分析、某轮审校等单项 | 完成该项后结束，不自动扩展为整篇生产流程 |

从用户当前请求及有效上下文判定并简要记录模式、交付范围、检查点、输入与输出路径。明确时不要让用户再选模式。指令只写“写文章”通常是 `end_to_end`；主题/平台等确有影响成稿的缺口，先读已有材料，再问最小问题。

## 授权边界

- 对明确提案的“可以”“好”“继续”等回复可批准该提案的具体范围，不要求固定口令；泛泛称赞、沉默和无关回复不扩展授权。含糊回复仅在确有范围歧义时澄清。
- 完成文章不等于发布、发送、调用付费生成服务或归档移动文件的许可。Stage 7 配图、Stage 8 归档仅在用户请求包含时执行；未请求的阶段记“不适用”，不为凑齐八阶段增加副作用。
- 发布必须有明确平台、账号、内容版本和执行授权；本写作流程默认仅交付本地稿件。图片 prompt 不等于图片已生成，稿件完成不等于已发布。
- 复用已确认的主题、立场、平台、素材和作者事实。涉及新增作者立场、个人经历、业绩或无法支持的事实，不得替用户编造；删除不可靠断言或明确标为待确认，完成不依赖它的部分。关键事实缺失时交付“含待确认项草稿”，不声称可直接发布。
- 阶段中的字数、素材数量、选项数量是相应长文/研究任务的参考，不覆盖用户明确的短稿范围。量化结论仍须有真实证据，不得为凑数字捏造数据、来源或第一人称实测。

## 工具、资源与工作方式

- `Read`、`TodoWrite`、`Task`、`AskUserQuestion`、`web_search` 等名称仅是能力示例。使用当前真实可用且获准的工具；缺少任务列表可用文本清单，缺少独立 agent 可顺序写作与自检，不虚称并行或独立评审。
- 多平台稿件可以在有授权且有实际独立 agent 能力时并行，也可以顺序完成；每个平台仍须单独适配并检查。缺少浏览能力或用户限定本地材料时，列明事实核验限制，不虚构检索。
- 从本次实际加载的 `SKILL.md` 定位资源，不从产品仓库 cwd 拼路径。本文件位于 `references/`；各 prompt 位于 `references/prompts/`，其中 `../persona/`、`../platforms/` 相对该 prompt 定位，模板在 `../../assets/`，脚本在 `../../scripts/`。不存在的历史文章是可选材料，不假定它存在。
- 用户指定的交付路径优先。`workflow/` 命名只是默认示例；已有 Brief/素材可直接引用，不为形式复制全套中间文件。需要恢复工作、明确检查点或用户要求时保存对应中间工件。保存后实际读取验证内容，不只检查文件名。
- 被委派者仅完成指定阶段并向协调者返回。返回应包含实际输出、检查、缺口与建议；**子 agent 返回不等于要求主流程暂停**。协调者依据模式决定继续、结束或在指定检查点等待，不把全部八阶段交给每个子 agent。
- 委派时传递模式、阶段、检查点、已确认材料、输出路径和副作用限制。没有独立执行能力时由同一执行者完成，准确标注自检。

## 完成标准

完成请求范围内的交付与实际检查，报告文件、模式、事实缺口和未执行项。`end_to_end` 的成稿检查覆盖逻辑/事实、风格、细节三个维度；这不要求三次人工审批，也不自动证明独立评审。检查点任务完成时清楚说明停在何处，不预先执行下一阶段。

写入或工具失败先检查原因，只做至多一次有依据的重试；仍失败则报告实际阻碍并保留已完成工作，不无限重跑。不得将失败、未运行或未完成写成通过。
