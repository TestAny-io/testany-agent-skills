**D35-P3-02　“被拒绝才算没有监听”的两个分支，以及“记录里的 Node”，没有被用例钉住**

本评审做了 14 项变异（第 5 节末），10 项有用例失败，3 项存活，1 项在沙箱里按预期存活：

- N1 把“1.5 秒内没有结果”改成算作没有监听，N2 把“任何连接错误”都算作没有监听：`tests/launcher.test.mjs:127` 照样通过。用例里只有“被拒绝”“连得上”“地址试不了”三种，没有超时，也没有别的错误码。实现是对的：禁止联网的沙箱里连接本机得到权限错误，`refused` 返回否（实测，第 6 节）。但这是整条规则里最要紧的一个判断，N2 的方向正是 82 提过的那种情形——连不上本机而读得到进程表时，把健康的服务当成留下来的。
- N6 把比对用的 Node 从“记录里的”换成“当前启动器自己的”，整个 `tests/launcher.test.mjs` 通过：用例里两者相同。
- N14 去掉读进程表时的 UTF-8 区域设置：沙箱里读不到进程表，用例放过；沙箱外这条用例会失败（本评审的探针：不带它时普通的 `ps` 读到的与启动时不同）。条文已如实写明自动化用例跑在读不到进程表的沙箱里。
- CHANGELOG 与 `37` 写“15 项变异全部有用例失败”，说的是作者选的那 15 项；不矛盾，但不等于新规则都被钉住。
- 建议：下一版让 `refused` 的连接可以由用例替换，补超时与别的错误码两种；补一条记录的 Node 与当前 Node 不同的用例。

**D35-P3-03　3.7 有两句还可以写得更准**

- `35`:766 与 `35`:767 的“已经没有监听，说明它过了写操作”，对 0.11.3 的服务成立；对 0.11.0～0.11.2 的旧服务差两类操作——Agent 管理与设置。这三个版本里它们不看关闭标记（`797397e` 的 `server/service.mjs` 里只有普通操作在第 2164 行看，已核对），监听关了以后仍可以经留下来的那条连接开始。v1.40 在“服务”一条里写了“此前不看关闭标记，v1.40 补上”，没有说到这一点对旧服务的含义。窗口很窄：要有人在旧服务已经关了监听的时候，正好经那条连接改 Agent 管理状态或设置。
- `35`:768 的括号“任一边没有摘要时只比来源路径，与 36b 7.4 对 0.10.x 任务不比摘要的做法一致”：0.10.x 写的任务是带摘要的（`36b` 7.1），两边都有时这里会比；两边算法不同的话，服务一侧仍按失败上报，要等启动器在下一次 `start` 里收尾。用例注释里“a 0.10.x job”没有摘要的说法同此。行为是保守的，只是类比不准。
- 建议：下一次修订各补半句。
