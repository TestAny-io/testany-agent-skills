# SkillDock 自身更新后的自动重启

## 需求与交互

2026-09-14，用户接受更新后自动 restart，无需热切换运行代码。本次补齐已批准更新功能的应用生效环节；不默认启用更新计划，不增加系统自启动。

- 用户选择 SkillDock 所属插件（当前为 testany-eng）并启用自动应用后，沿用既有来源校验和包级更新。
- 安装结果确认、整批更新完成后，准备新版并自动重启。手动更新同样适用。
- 保留数据目录、项目、端口、更新计划、历史、外观与语言。浏览器显示准备/重启状态，恢复后重新加载新资源并获取新会话；不重放中断的写请求。
- 构建失败保留旧服务；新版启动失败尝试恢复已验证的旧运行目录，明确报告失败，不能将包更新成功等同应用启动成功。

## 工程设计

- 安装身份由 Codex 配置根、marketplace、plugin 名及 skill 相对路径确定，不包含版本目录。仅相同已核实安装身份可共用状态；其他源码实例仍拒绝接管。
- 启动器先准备隔离 runtime，再停止记录和健康检查均匹配的旧进程。启动新进程并保存记录；失败时先清理本次创建的进程，再从保留的旧 runtime 恢复。
- 服务在安装变化后通知重启协调器。协调器只在写操作及 scheduler 均空闲时暂停新写操作，解析当前已安装版本并核验源码差异，然后派生独立启动器。新进程不依赖旧进程存活。
- 重启状态写入应用 state 内的 restart.json；健康响应增加进程实例标识、源码摘要与重启状态。状态接口只读且沿用 Host/Origin 边界。
- 浏览器轮询健康状态；发现实例变化重新加载页面，保留当前导航位置，获取新 token。写请求失败不自动重试。
- 正式服务才启用协调器；测试可显式注入执行器和时钟，不操作用户配置。通过 npm start 直接启动、缺少 launcher 所有权记录的服务不自动接管。

## 验证范围

1. 同插件跨版本保留状态、其他实例及越界来源拒绝接管。
2. 先构建后停机；构建失败旧 PID 存活；新进程失败恢复旧服务。
3. 后台计划更新自身后仅在整批结束时触发一次重启，保留计划和历史；重启期间拒绝新写操作。
4. 浏览器重连、加载新实例、三语言状态、主题与导航保留，不重发写请求。
5. 类型检查、构建、相关 Node/浏览器回归与源码包可复现检查。
