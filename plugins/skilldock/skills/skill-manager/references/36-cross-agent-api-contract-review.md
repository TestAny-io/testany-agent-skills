### 6.2 0.10.3 转交链（36b 4、5 节）

- **步骤与分支**：`start` 的四步与 `restart/status/stop` 的两步清楚；第 2 步例外（DG-RUNNING-PROJECT）的下游失败没有回落（P1-01）。
- **有效项目**：判定可实现、可测。
- **第 2 步核实**：与 0.10.2 原生入口的核实一致，且多了 `appVersion`、`dataGeneration` 与 `state` 规范路径的检查。
- **第 3 步目标与兜底**：可实现。有两处宜写清：
  - 条件 6 未比较 marketplace 名（P2-05）；
  - 由启动记录派生的缓存根使条件 1 对 `preferred` 自证成立（P2-06）。
- **下游结果与输出**：退出码清楚。stdout 直接继承时，回落场景无法保证“只有一个 JSON”（P2-03）。
- **目录与本安装识别**：
  - 自定义 Codex 目录：环境变量、默认值、记录派生三路；
  - 自定义 Claude 目录：根目录记录、环境变量、默认值、记录派生；
  - 开发安装：第 1、3 步不可用；
  - `.orphaned_at`：本安装识别只看形态，候选目标排除废弃目录。
  四类情形均有规定。
- **死循环风险**：第 1、3 步只调用 ≥0.11.0 的安装，不会直接回到 0.10.3。但契约没有禁止 0.11.x 调用较旧的启动脚本，0.10.3 也没有利用已存在的 `SKILLDOCK_HANDOVER` 拒绝重入，宜加防护（P2-02）。

### 6.3 来源标识规范化与等价（36a 9）

- **真实记录（只读、仅取所需键、URL 用户信息已脱敏）**：
  - Codex `~/.codex/config.toml`：表头为 `[marketplaces.testany-agent-skills]`，键为 `source_type = "git"`、`source = "https://github.com/TestAny-io/testany-agent-skills.git"`；其他 marketplace 有 `source_type = "local"`。
  - Claude `~/.claude/plugins/known_marketplaces.json`：顶层以名称为键，条目键为 `installLocation`、`lastUpdated`、`source`；`source` 有两种形态：`{"source":"git","url":…}` 与 `{"source":"github","repo":"owner/repo"}`。
  - 两者与 36a 9.1、9.2 一致。
- **字面实现实验（`norm36a9.py`）**：
  - 官方仓库的 HTTPS、SSH、scp、`owner/repo`、带凭证、带端口、`.git/` 结尾等写法，都规范为 `github.com/testany-io/testany-agent-skills`；
  - fork 得到不同标识，本地路径不可核实；
  - 凭证经规则 1 去除。
- **未发现过宽（误判同源）**。按字面规则，`git://`、`file://` 与 `C:/…` 会被 scp 规则解析出 host，但得到的标识与官方不同，结果仍失败安全；`#ref`、`?query`、百分号编码会导致合法写法不被认可（偏严）。冻结前宜写清（P2-04）。

### 6.5 HTTP 增量（36c）

- **健康检查冻结字段**：
  - 与 0.10.2 启动器、原生入口、0.10.3 第 2 步的读取一致（`index.mjs:31`、`native-backend.mjs:105-106`）；
  - 0.10.x 原生界面每 1.5 秒读取 `restart` 与 `instanceId`（`src/useRuntimeConnection.ts:18-33`），`restart` 却被标为“不冻结”（P2-07）。
- **接口版本规则**：
  - 不带 `multiAgent` 只返回 Codex 对象、不带 `agent` 按 Codex 处理，能保证 0.10.x 原生界面经代理访问 0.11 服务时可用；0.10.x 原生入口的白名单（`native-backend.mjs:12-16`）也挡住了 2 版参数。
