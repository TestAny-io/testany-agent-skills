#### IF-P3-01 启动器：保存项目提示去掉了 `SKILLDOCK_HANDOVER` 条件，对不按 36b 6.2 调用的转交比原条件弱

- 位置：`scripts/launch.mjs:270-271`；判定函数 `assets/app/server/project-context.mjs:40-46`。
- 问题：原条件是“来源为 saved、最终目录就是它、**不是转交**、规范化后的工作目录不等于项目”。新条件把后两项换成“工作目录是数据目录之外的有效目录，且不等于项目”。新旧条件在三种形态下结果不同（实测，第 3.2 节）：

  |------|--------|--------|------|
  | 0.10.2 原生入口形态（`--project` 与工作目录都是 `compat/legacy-project`），有保存的项目 | 写 | 不写 | 这正是 UF3-P3-02 要的 |
  | 非转交，工作目录在数据目录内，有保存的项目 | 写 | 不写 | 与“数据目录不算调用目录”的说法一致，可以接受 |

- 建议（可选）：两个条件都留着，即在 `caller` 的计算里保留 `env.SKILLDOCK_HANDOVER !== '1'`。对照变异 L10 这样改之后 `launcher.test.mjs` 30/30 通过（实测），一行即可，协议信号与目录约定互为备份。

  | 条目指向副本内一个不存在的目录 | `[]` | 界面显示“专用 manifest：无”。其实是没读到，按契约的口径应当省略 |
  | 插件目录在副本内，但它的 `.claude-plugin` 是指向副本外的链接，或 `plugin.json` 是指向副本外文件的链接 | `["claude"]` | 越界检查只做到插件目录一层；`fs.access` 跟随链接。只判断存在与否，不读内容 |
  | `plugin.json` 是一个目录 | `["claude"]` | 存在即算有 |
  | `source` 为空串 | 有 `pluginRoot` 时取 `pluginRoot` 本身，得到 `[]`；没有时取 marketplace 根，得到根上的 manifest | 空串不是有效的相对路径 |

- 其余边界都按预期（见第 4.4 节）：相对路径越出副本、绝对路径、指向副本外的目录链接、对象或非字符串的 `source`、没有 `source`、条目不存在、`installLocation` 不存在或不是字符串或是相对路径、`marketplace.json` 损坏，一律返回空并省略字段，预览照常返回。
- 另一处不一致：预览只从 `known_marketplaces.json` 取 `installLocation`（`claude-actions.mjs:182`），而清单优先用命令行列表给的值、其次才是记录（`claude-catalog.mjs:311`），更新流程用的是列表的值（`service.mjs:800`）。两者不同时预览会静默地不显示或读到另一处。
- 影响：都只影响安装预览里一行证据的准确性，不影响安装。
- 建议：先确认目录存在且是目录，否则返回空；判断 manifest 时用 `lstat` 加 `isFile`（或对文件再做一次真实路径在副本内的检查）；空串 `source` 直接返回空；`installLocation` 的取法与清单统一。各补一条断言。

#### IF-P3-07 UI-15：联网提示附在所有 `npm ci` 失败上

- 位置：`assets/app/server/runtime.mjs:49-51`；用例 `assets/app/tests/launcher.test.mjs:460-469`。
- 问题：`npm ci` 以任何原因失败都会追加“安装依赖需要联网，请确认网络可用后重试”。锁文件损坏、磁盘或权限问题、子进程 300 秒超时被终止（此时写成“失败（null）”）都会得到这句。新用例正是用损坏的锁文件触发的，本身就是一次与网络无关的失败。
- 已核对无误的部分：`npm ci` 与 `npm run build` 区分正确，提示只接在前者上（N1 去掉提示、N2 去掉启动时的说明、N3 把提示也接到构建上，三个变异都被发现，实测）。报错文字的去向（阅读）：命令行入口经 `failureText` 写到 stderr，退出码仍是 1；重启任务写进 `restart.json` 的 `message`；原生入口显示“SkillDock 后台启动未完成。”加 stderr 末尾 2500 个字符，这句话在末尾，能看到。
- 相邻的旧问题（早于本批）：`run` 的报错写的是“`<node 路径> <npm-cli 路径>` 失败（码）”，不写是 `ci` 还是 `run build`；现在只能靠有没有联网提示来分辨。
- 影响：非网络原因失败时，这句话会把人引向检查网络；后面跟着“详见 build.log”，能纠正回来。
- 建议：措辞改成不下判断的说法，例如“若本机离线：安装依赖需要联网，请联网后重试”；或者把步骤名写进报错（“安装依赖失败”“构建失败”）。真正断网时 `npm ci` 的表现没有实测（见第 5 节）。

## 6. 其他观察（不计入问题数）

- 标题旁的数字与右侧筛选按钮上的数字仍是两组口径：插件页标题数的是“已安装的插件”，筛选按钮数的是当前分类下的插件（探针中标题为 0、0、0，按钮为 3、2、1）。UI-03 的处理是把说明放进悬停提示与读屏文字；键盘与触屏用户看不到悬停提示。是否要有可见的说明，属于整体重新设计的范围。
