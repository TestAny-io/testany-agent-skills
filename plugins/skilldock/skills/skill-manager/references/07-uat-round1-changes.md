# SkillDock 第一轮 UAT 变更基线

状态：六项反馈已形成需求、界面与工程变更并完成实现；整合验证通过，第二轮 UAT 待用户验收。日期：2026-09-14。

## 输入、授权与范围

来源 `UAT-SD-R1-001`：用户在第一轮 UAT 要求深色模式、AGPL 开源许可、中文/英语/日语、分类解释、既有安装来源与各类更新、可配置的循环自动更新，并随后要求继续。本轮沿用原始研发顺序：需求变更 → 界面设计 → 工程设计 → 实现 → 验证。用户授权实施这些本地软件功能；测试仍仅在隔离数据上执行写操作，真实环境仅检查清单。新定时计划默认关闭，由使用者在界面中配置后启用；本轮不代替用户创建真实更新计划。

此文件作为 v0.1 文档的有限增量，变更覆盖 REQ-SD-001/002/006/007/008/009/010 并新增 011–014。原始来源、冲突保护、结果读回、演练隔离继续有效。原 UAT 与源码审查结论不自动覆盖本轮代码。

## 界面设计

- 保留五个主页面和现有浅色布局。顶栏“外观与语言”打开偏好弹窗，提供三种外观、三种语言，以及许可证与对应源码下载入口。
- 深色使用墨绿灰背景、暖灰正文与橘色主按钮，使用主题变量覆盖浮层、输入、焦点、禁用与状态色；不用滤镜反色。
- 统计卡下方有常驻一句解释；异常卡直接显示原因文字。详情仍保留文件路径、证据和所属插件跳转。
- 更新页按所有者组织完整清单；每项展示“来自哪里、装在哪里、由谁更新、现在能做什么”。可关联来源的旧技能有“关联更新来源”；附带技能定位所属包；真正无法调用的宿主更新有明确下一步。
- 更新页增加“自动更新”设置：开关、周期（每小时/每天/每周及自定义间隔）、当前环境目标选择、预计下次、上次汇总与记录入口。保存配置清楚显示仅检查/自动应用、周期、目标数量和时区；同名目标选项显示安装路径，来源关联与更新确认也显示目标和来源路径。
- 实际源内容与原始 CLI 细节可展开，说明性文案本地化；既有未知错误保留，不隐藏失败信息。

## 工程设计与保持项

- React 显式字典和参数插值；偏好存储 `skilldock.preferences.v1`，含 `language=zh|en|ja` 和 `theme=light|dark|system`。默认沿用浅色中文。使用 `Intl` 格式化时间，监听系统主题变化。
- 来源证据区分已核实安装记录、已声明元数据、用户关联及未知。公开投影去除凭证；真实来源不进入任意读取接口。Git 工作目录仅用于推导来源/版本，更新不隐式 pull 用户工作树。
- 现有 Codex CLI 已在独立临时环境验证：相同 ID 再次 `plugin add` 可安装新版本，但会将禁用插件启用。包更新适配器因此捕获旧状态、更新、恢复禁用设置、重新读取结果；恢复失败必须报告部分完成，不称成功。
- 后端调度由本地服务承担，与浏览器计时器和当前 Codex 对话无关。周期定义为固定分钟间隔，支持15–10080分钟；时区只用于清楚显示，不冒充每天当地某一时刻。服务暂停/电脑休眠时不执行，恢复后仅补一轮，再计算下次。停止服务/重启电脑后的启动条件在界面和运行说明中明确。
- 每个环境持久化自己的计划和运行状态；显式目标列表不自动纳入未来新增对象。到期重读能力和内容指纹，按所属插件去重。单进程互斥与持久化运行记录避免重复；启用/禁用和重启恢复需测试。
- 保存计划时同时绑定当时的来源/所属管理器及安装身份；相同路径删除重装或重新关联来源后，不复用旧授权，跳过并要求重新选择。正常由该计划成功更新后刷新其绑定。来源关联预览在确认时重查来源和已安装目标指纹。
- 遗留 `running` 批次在服务启动后标为结果未确认，并通过新一轮读取/检查核对现状，不能直接重放之前的写请求。每轮结束后按结束时间加间隔计算下次；到期但服务忙碌则稍后执行一次。关闭计划不再启动后续对象，已开始的单项完成其事务收尾。
- 许可证和源码下载只能返回软件构建时打包的固定文件，不读取用户目录。源码必须对应运行代码，包含重建所需脚本和声明，不包含本机技能库、状态、凭证或依赖缓存。
- 共享 API 类型是 wire 契约事实源；新增字段尽量兼容旧清单，错误继续有稳定 code。契约已实现 update.check/apply、skill.previewSource/connectSource、updates.run 和 schedule.configure；分别返回更新对象、来源预览、运行记录与持久计划。
