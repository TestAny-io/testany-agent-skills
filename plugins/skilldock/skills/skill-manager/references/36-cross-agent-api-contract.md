## 2. 范围与边界

覆盖：
- 0.10.3 发布后无法再改的跨版本识别面：数据代号、启动记录新旧字段、Claude 根目录记录、计划文件版本、旧项目固定子目录、安装识别、来源标识等价、启动脚本调用约定、转交链、退出码与输出、健康检查字段；
- 0.11.x 为与 0.10.2、0.10.3 共存必须承担的义务；
- 0.11.0 的 HTTP 接口增量（多 Agent 字段形态、接口版本规则、新增操作与错误码）；
- 兼容测试矩阵的期望结果。

不覆盖：0.11.x 内部数据结构、算法、锁的实现细节、重试次数与界面交互（随代码评审）；宿主（Codex、Claude）自身的文件格式（只冻结 SkillDock 的读取方式）。

数据所有权：
- `<state>`（默认 `~/.local/share/skilldock`）只属于 SkillDock；
- 宿主配置、插件缓存与 marketplace 记录属于各宿主，SkillDock 只读这些文件；对宿主的写入一律经宿主命令行或 HLD 3.4 规定的结构化补丁。

## 3. 共享规则

| 规则 | 内容 |
|------|------|
| 认证与授权 | HTTP：仅 `127.0.0.1`；Host、Origin、跨站标记校验；写请求需会话令牌（36c 第 10 节）。进程间：只执行经核验的安装中的启动脚本（36b 第 11 节）。文件：权限 `0600` / 目录 `0700`，原子替换 |
| 错误体系 | HTTP 沿用 `{error:{code,message}}`；新增错误码见 36c 第 8 节。命令行沿用“退出码 + stderr 原因 + stdout JSON”，stdout 只有一个 JSON；0.10.3 新增退出码 3（需要更新本侧，36b 第 10.4 节）；0.11.x 另有退出码 4（迁移门槛未通过（含归属判定），或迁移失败后对同一目标的重启任务被快速拒绝，见 36b 第 6.3 节）；0.11.x 的 `start`、`restart`、`status`、`stop` 非 0 退出时 stdout 为空；0.10.3 的退出码 3 仍按 36b 第 10.3 节输出（冻结）；`doctor`、`cli` 沿用 0.10.2 |
| 版本与兼容 | 文件与命令行的冻结面见 36a 第 11 节、36b 第 12 节；HTTP 的 `apiVersion` 规则见 36c 第 5 节。冻结面只增不改；停止与 0.10.x 共存须由 Owner 决定并在发布说明中写明 |
| 失败方向 | 读不懂较新数据时不接管、不改写（0.10.3）；无法确认宿主状态时只读（0.11.x） |
| 幂等与重试 | 启动脚本 `start` 幂等（实例已在运行即沿用）；HTTP 写操作发出后不自动重试（沿用原生入口约定）；读回不一致不自动重试；0.10.3 自更新失败后退避（36b 第 7.3 节） |
| 限流与配额 | 不适用（本机单用户）；输出量与超时限制见 36b 第 6 节 |
| 可观测性 | 启动链诊断写 stderr 与 `<state>/server.log`；所有输出中的 URL 凭证脱敏；不记录设置文件中的无关键值 |

## 8. Guardrails Trigger Check

结论：`no_trigger`。本契约只约束 SkillDock 自身各版本之间的文件、进程与 HTTP 接口，不改变仓库中其他插件或模块须遵守的默认规则。
