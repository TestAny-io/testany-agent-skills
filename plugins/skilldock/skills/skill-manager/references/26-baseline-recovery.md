# SkillDock 0.4.2：核实外部同步并恢复更新

## 已确认的问题

种子用户在另一台电脑报告 `testany-eng 2.4.1` 持续出现 `LOCAL_CHANGES`。仓库提交 `b81cbd2` 修改了插件内测试文件，未增加插件版本。使用该提交前后的真实包在隔离目录复现：安装内容与来源已完全相同，但旧基线检查提前返回，无法到达一致性判断；重启不能恢复。定时计划保存的旧内容指纹还会触发 `TARGET_BINDING_CHANGED`。

0.4.1 修复的是后台健康状态与历史批次混用；本轮处理实际检查被过期记录阻断的问题。远端缓存具体由哪次安装或刷新同步仍未知。

## 恢复规则

1. 检查插件时先读取已核实来源和完整内容。旧基线发生变化但安装版本、内容与来源完全一致，可以恢复基线；仅更新 SkillDock 元数据，不覆盖安装文件。
2. 定时计划只允许恢复内容指纹变化。插件、来源/所有者、路径、设备、目录 inode 和代次等原绑定身份必须保持一致；更换来源或替换安装目录仍需明确重新选择。
3. 恢复绑定前使用现有来源快照进行核实，不先执行可能改变插件安装的 marketplace refresh。核实后才允许常规检查；常规刷新过程中发生的同版本同步也会在本次检查内恢复绑定。
4. 来源必须有唯一、可验证的版本 authority；组件映射不得越出包根。核实过程复查来源声明、目录边界和完整指纹；任何变化均停止恢复并清理暂存数据。
5. 成功恢复留有操作记录，中文、英文、日文同步。原计划的频率、目标、自动应用设置、启用状态和历史批次不会被重建或清空。
6. 来源已推进到其他内容、安装有独有修改或来源无法核实时，保留更新保护。不能仅删除基线或忽略 `LOCAL_CHANGES` 强制接管；此修复不把旧安装认作任意新版内容。

## 验证

使用隔离 HOME、Codex 目录、marketplace 与状态目录；不访问种子用户电脑，不操作当前用户的插件或正在运行的 SkillDock 服务。回归覆盖手动恢复、重启后的定时恢复、单独过期的计划绑定、检查过程中的同版本同步、真实本地修改、来源/目录替换及核实期间的并发变化。

2026-09-23 执行结果：

- 新增 11 项针对性回归；最初的恢复用例先在 0.4.1 上复现失败。修复后完整 `node --test tests/*.test.mjs` 为 150/150 通过，0 失败、0 跳过。
- 通过实际 `background-worker.mjs` 入口，在关闭测试 Service、没有 Web 服务的情况下补做过期计划，确认后台结果成功、基线与绑定恢复、没有执行插件安装命令。
- 使用 `b81cbd2` 前后的真实 `testany-eng 2.4.1` 包做隔离复测：仅来源变化仍为 `VERSION_UNCHANGED`；安装也同步后，定时检查无需先手动检查即可恢复；重复检查、重启后检查正常；后续来源 2.4.2 可被识别为可更新；独有本地修改仍为 `LOCAL_CHANGES`。
- `npm run build` 的 TypeScript 检查、生产构建、许可及对应源码打包通过。
- 仓库发现静态检查通过（34 个 active skills），`git diff --check` 通过。

本轮没有调用真实用户的 Codex 插件安装/刷新操作，也没有在种子用户电脑执行测试。CLI 的清单与刷新行为通过隔离适配器控制。macOS 系统任务注册与启动代码未修改，本轮没有重复注册真实 LaunchAgent；验证重点为恢复逻辑、后台 worker 入口及其失败保护。
