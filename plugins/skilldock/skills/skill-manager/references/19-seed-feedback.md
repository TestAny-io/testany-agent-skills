# 首位种子用户反馈整改

## 需求

2026-09-15：安装与运行已成功，用户确认将 SkillDock 改为独立 skilldock 插件。新安装只包含一个应用入口，已有 testany-eng 用户保留原数据，整套研发工具不被自动卸载。修复 CLI 发现回退不足；提供明确项目参数与 GUI 项目切换，打印请求目录和实际扫描目录；提示中断调用不等于后台服务已停止。

反馈中具体启动路径和健康检查路径在转述时丢失；不能声称已重现同一台机器的问题。当前可确认的缺口是桌面应用 CLI 未作为候选，路径规范化没有说明，项目选择只能靠 cwd/环境变量。

## 界面与契约

当前项目栏增加“切换项目”，弹窗输入本机绝对目录，展示当前扫描目录与目录来源；失败保留旧清单，成功立即重扫。个人及插件清单继续可用，切换后提示核对既有计划目标。

启动入口增加 start --project <绝对目录>；优先级为显式参数、环境变量、GUI 保存选择、调用工作目录。启动输出与 health/state 提供 requested/effective/source 信息，路径不同解释符号链接或选择来源。status/stop 始终以已验证实例为准，不因调用目录变化操作其他服务。

新增 project.select 本机写请求，使用现有 token/origin 校验和互斥控制。验证目录存在、目录类型及真实路径，再捕获新扫描根边界；保存选择成功后切换，既有操作预览失效，计划与历史保留。服务身份使用启动实例标识，项目切换不破坏停止、自更新核实。

## 工程实现

独立插件保持 skills/skill-manager 路径以兼容用户入口，迁移移动整个应用子树，不使用越界 symlink 或代码复制。新插件 manifest 为单一版本来源；testany-eng 移除该入口。旧包数据只能通过显式迁移参数从同一 marketplace、Codex 根和固定旧插件身份接续。

CLI 选择为依赖无关模块，共用于启动诊断与业务适配器。逐个验证版本与 plugin help；PATH 损坏时继续尝试桌面应用和 Codex 管理的 CLI，输出最终绝对路径。显式覆盖无效时返回明确错误。

## 验证

覆盖损坏 wrapper、缺少 plugin 命令、应用路径含空格；项目参数优先级、符号链接、无效目录、切换后的技能清单及保存恢复、并发更新与过期预览；服务状态/停止和自更新保持；独立 marketplace 实际隔离安装仅包含一个技能，旧身份迁移保留数据。GUI 验证中英日、深浅主题、项目弹窗与失败信息。本轮尚未发布。
