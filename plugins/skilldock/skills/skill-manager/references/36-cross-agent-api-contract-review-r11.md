## 5. 重点核查

### 5.1 36b 6.3 退出码 4 的新写法：按 1a 复核

新条文（36b 第 204 行）只在退出码 4 的定义中补了“含启动记录属于 Claude 侧低于 0.10.3 的安装，只在 `start`、`restart` 中”。HLD 11A 条件 1b 规定，0.10.3 赖以处理被调用方结果的完成条件与输出限制，修订时按 1a 复核。复核只问一件事：新写法是否要求改变 0.10.3 或 0.10.2 的冻结行为。

| 核对项 | 证据 | 判断 |
|--------|------|------|
| 冻结调用方只区分 0 与非 0 | `337547a` 的 `handover.mjs` 第 289～291 行（只在退出码为 0 时转出 stdout）、第 348、377 行（只判 `=== 0`）；`native-backend.mjs` 第 116～125 行（`execFile` 非 0 即抛错）；`self-update.mjs` 第 25 行（非 0 即“重启启动器退出”） | 一致；4 的来源多一种，不改变任何冻结调用方的分支 |
| stdout 为空、原因写 stderr | 实验 E1、E2：`start` 退出 4、`stop` 退出 1，stdout 都为空，stderr 为原因加 2 条处理步骤 | 与 6.3“这四个动作非 0 退出时 stdout 为空”一致 |
| 只在 `start`、`restart` | `launch.mjs` 第 204～206 行 `gate = ['start','restart'].includes(action)` | 一致 |
| 0.10.3 退出码 3 的冻结输出、`doctor`、`cli` | 未改 | 不受影响 |

结论：**不要求改变 0.10.3 或 0.10.2 的行为**。条文措辞“属于 Claude 侧低于 0.10.3 的安装”与 HLD 3.7 第 724 行“视为‘低于 0.10.3 的 Claude 侧安装’”一致；实现按“0.10.x 目录形态记录的来源位于 Claude 插件缓存根下”判定（`launch-plan.mjs` 第 162～166 行），不看版本、废弃标记与实例是否存活，由此产生的问题见第 10 节范围外观察 1。

**APIR11-P2-01 跨侧计划目标的确认：范围与可见性（建议在实现阶段 5 的后台计划之前处理）**

- 有效依据：

- 当前问题：
  - (a) **确认范围可能大于确认框所列。** 例如计划已是自动应用，目标 X 是保存之后才启用另一侧管理而待确认的；用户新增目标 Y，收到 `CONFIRMATION_REQUIRED`。条文没有写这次的 `nativeRules` 是否也列出 X。若只列 Y，用户确认后 X 也一并转为自动应用，改写的是用户没看到的另一侧插件内容。

- 影响：阶段 5 实现时，或者确认框与确认范围不一致，或者由实现自行增加线上字段而不经契约（字段形态属 11A 条件 1b）。

  - 在 36c 第 6 节为计划目标增加只供 0.11.x 界面使用的确认状态（例如 `multiAgent=1` 时给出 `confirmation?: "pending" | "confirmed"`，只用于这类目标），随 `contracts.ts` 增量；
