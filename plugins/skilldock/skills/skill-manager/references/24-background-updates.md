# SkillDock 0.4.0：独立后台更新

## 产品依据与范围

2026-09-23，用户确认“系统唤起 → 检查并更新 → 退出”，授权正确实现并升级 minor。保留 Codex 插件与网页面板形态；本次不创建独立桌面应用，不引入 Codex Automation，不扩大既有更新目标与自动应用权限。

- macOS 当前用户启用计划后，关闭网页服务和 Codex 不影响调度；重启并登录后恢复。
- 休眠、关机、离线错过的周期只补做一次；失败保存原因并退避重试。
- 关闭计划阻止后续对象，当前单项安全收尾。成功安静记录，失败在更新页明确展示。
- 网页读取实际后台注册状态、上次唤起、运行结果、下次到期时间；系统禁用任务时不显示运行正常、不自行重新启用。
- 已有计划在新版首次启动时迁移，原目标、身份绑定、周期、历史保留。Windows/Linux 本轮不新增系统调度适配，不宣称支持。

## 界面与契约

更新页保留小时设置，增加后台任务状态与最近唤起/错误；设置中说明会注册当前用户后台任务。中文、英文、日文同步。`UpdateSchedule` 增加可选后台状态与失败重试/成功时间；旧持久化 v1 记录可读。已有 API 动作保留。

## 工程设计

1. `launchd` 用户 LaunchAgent 使用固定数据目录中的入口，登录以及每五分钟触发轻量到期检查。使用 calendar 触发以便睡眠后补做，不使用 KeepAlive。检查尚未到期时不扫描技能、不访问网络，不打开 HTTP 端口。
2. 独立 worker 复用 service/scheduler 更新逻辑，执行一批后退出。HTTP 服务不再拥有自动更新计时器；手动更新复用同一执行逻辑。
3. Codex 数据根上的跨进程锁串行化所有 SkillDock 写操作；UI 可读取持久化进度。只有持锁者可恢复中断记录，避免新窗口误将活跃任务判为中断。来源和内容绑定检查继续适用。
4. 计划、项目、目标绑定、执行结果保存在数据目录。独立停用标记允许用户在执行过程中取消后续对象，避免并发重写执行历史。
5. 固定入口保存绝对 Node/CLI/数据根/项目上下文，仅保存必要的非敏感环境变量。运行时寻找用户已配置的 Git 凭据；不复制 token，不依赖交互式 shell 或旧 SSH agent socket。锁定凭据作为失败记录。
6. 固定入口与隔离运行目录不位于插件版本缓存。检测到自身安装升级后准备新的隔离运行目录，下一次调用使用新版本；未打开面板时不启动面板。构建失败保留已知运行版本并记录重试原因。
7. 启用计划必须读回系统注册成功；注册失败不提交开启状态。已启用计划首次迁移失败保留原配置并显式报错。停用/卸载清理注册项；无法可靠判断已卸载时保留并报告错误。

## 交付与 UAT

已有启用计划在新版首次启动时迁移，保留原目标、周期和自动应用选择。应用更新后的自动重启也会完成迁移，无需额外手动打开；仅更新了插件文件、尚未运行新版时，才需手动启动一次。原本未启用的计划不会因升级而自动开启。此后可关闭面板、停止网页服务或退出 Codex。定时任务属于当前登录用户，电脑关机时不运行，开机并登录后补做。手动关闭自动更新会移除系统任务。

本轮未实际重启电脑、使电脑休眠或关闭当前 Codex，也未访问用户的远程私仓，以下场景交给 UAT：

1. 选择一个可更新的测试目标，启用计划与自动应用；关闭 SkillDock 网页服务和 Codex，等待到期，再打开面板核对文件与运行记录。
2. 重启电脑并登录，保持 SkillDock 关闭，验证过期计划补做一次；休眠跨过到期时间后唤醒，验证同样行为。
3. 网络断开时运行，确认失败原因和退避时间；恢复网络后验证成功，且不回放旧写请求。
4. 使用用户已有权限的私仓，分别验证 HTTPS/SSH 凭据可用、钥匙串锁定或授权不可用时的结果。
5. 在系统中禁用后台任务，确认更新页显示受阻，应用不会自行解除禁用；应用内停用计划后读回系统任务已移除。
