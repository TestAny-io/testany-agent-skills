# SkillDock 0.4.1：后台状态与更新结果

## 问题与修复范围

种子用户截图中，“最近唤起”为 9 月 23 日，“上次运行”仍为 9 月 15 日，却显示同版本内容变化导致执行失败。隔离复现确认：已安装插件首次唤起时会核对安装身份，即使计划未到期，0.4.0 仍读取历史批次并把其中的错误写入当前后台状态；本次新增更新批次数为零。

- 后台状态只记录本次任务的运行健康。仅维护安装/运行目录或等待计划到期时，结果为 `idle`；只有本次新建的更新批次才关联 `lastRunId`。
- 单个对象的失败或跳过留在原批次中，保留重试逻辑。更新页分别显示后台任务状态和带时间的上次检查结果。
- 状态格式增加 `format: 2`。0.4.0 中带应用版本、无 `retryAt` 的旧错误来自批次结果，读取时不再当作运行错误；带重试时间的真实 worker 错误、没有应用版本的入口错误继续保留。格式升级不修改历史更新数据。
- 真实运行错误保存 `errorAt`，等待重试时不把错误时间改成最近唤起时间，恢复成功后清除。
- 更新条目保存对象名称/标识、当时比较的版本和 `occurredAt`。旧记录缺少版本时明确显示未记录，不根据当前安装补造历史。
- 不放宽同版本变更、降级、来源身份和本地修改的检查。插件内随包分发的文档/图片变更也需要发布新版本，本轮升级为 0.4.1。

## 验证

新增四项回归先在旧实现上执行，均以预期断言失败：首次未到期唤起误用历史结果、真实运行失败时间、旧状态读回、插件结果缺少版本与时间。

修复后于 2026-09-23 完成：

- `node --test tests/*.test.mjs`：139 项通过，0 失败、0 跳过。覆盖旧状态迁移、真实错误的退避与恢复、历史批次不被改写，以及新结果的对象/版本/时间持久化。
- `npm run build`：TypeScript 检查、生产构建、许可与对应源码打包通过。
- `node tests/background-launchd-smoke.mjs`：在隔离 HOME 和状态目录中使用真实 macOS LaunchAgent，确认 0.4.1 启动、过期计划补做、文件更新、退出码 0；自身更新到测试版本 0.5.0 后，下一次系统唤起运行该测试版本；删除测试来源后自动注销任务。0.5.0 仅为测试数据。
- Playwright 浏览器验证：中文浅色显示旧记录与未记录的历史版本；英文深色通过“检查全部”产生并显示真实的同版本阻止结果，保留对象、0.4.1 比较版本与时间；模拟真实运行错误时显示原始错误时间；日文 720px 窄窗口显示健康的未到期状态，无横向溢出。浏览器仅出现既有的 `favicon.ico` 404，没有应用 JavaScript 异常。
- `validate_codex_compat.py --profile repository`：34 个 active skills 静态检查通过；`git diff --check` 通过。

本轮验证使用隔离安装与状态目录，不修改用户插件、自动更新计划或正在使用的 SkillDock 服务。种子用户电脑上的原始历史来源未经直接读取；修复依据为截图所示行为的本地复现，而非对该用户历史来源的推测。
