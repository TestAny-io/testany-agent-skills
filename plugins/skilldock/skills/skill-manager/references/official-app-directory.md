# 官方应用目录接入

在维护官方目录的展示、搜索、安装、授权或排查 `app-…` 条目时读取。

## 数据与安装边界

- `codex plugin list --available --json` 仍是插件身份、安装状态和安装策略的来源；`name`/`id` 不被展示名称覆盖。
- 使用当前 Codex CLI 启动短生命周期 stdio app-server，通过 `app/list` 分页读取名称、介绍、图标和账号连接信息，通过 `app/read` 读取预览。只匹配来源中 `plugin_<app id>` 与应用 ID 的精确关系，不按品牌名模糊合并，不硬编码 Miro。
- `plugin/list`、`plugin/read`、`plugin/install` 等 app-server 方法在官方文档中标为开发中且不建议生产客户端调用，产品不使用这些方法。安装沿用 `codex plugin add <原始插件 ID> --json`，并重新读取 CLI 清单确认；内部映射没有对应应用的远程条目继续受保护。
- 用户先预览，再确认安装。预览期间不安装、不连接账号。安装前重读策略、版本和应用身份；安装失败或响应中断不自动重试。安装与账号授权分别显示，账号连接走 `app/read` 返回并通过校验的官方 HTTPS 地址。
- `app/list` 的可访问状态作为连接可用性证据，不代表已经实际调用 Miro 工具。完整组件清单与逐项技能选择未由该 API 暴露，界面明确说明，不用空技能数组声称插件没有技能。

## 图标与兼容性

- 图标由后端按已知插件 ID 读取，前端不接收任意图片代理 URL。只允许指定 OpenAI CDN 的 HTTPS、逐跳验证重定向、不附带账号凭据、限制时间/大小/并发、校验图片或自包含 SVG，转换成 data URL 后经现有浏览器/MCP 通道渲染。
- 只为可见条目加载，缓存有界；加载失败使用既有图标。官方应用目录读取有分页、超时、缓存和错误提示，失败不影响 CLI 本地目录或个人技能。
- 既有目录、更新、权限和文件边界保持原有路径。新功能不安装全局 Node，也不读取、复制或输出用户凭据。

## 验证

- `tests/remote-directory.test.mjs`：目录分页、缓存/失败、身份关联、策略限制、预览与 CLI 参数、版本变化、安装/授权分离、结果不明、图片边界和 stdio 生命周期。
- `tests/remote-directory.spec.ts`：中英日、浅深色下的搜索、跨筛选提示、图标、预览和模拟安装/授权流程；使用隔离数据，不安装用户的 Miro。
- `tests/plugin-selection.spec.ts`、现有安全/自定义目录/原生协议用例覆盖原安装流程和新资源通道。
- 发布前重新构建 Web 与 native 资源，执行相关测试并按仓库规则升版；源码验证不代表用户的真实 Miro 授权已经完成。

依据：[OpenAI app-server 文档](https://learn.chatgpt.com/docs/app-server)，以及本机 Codex CLI 生成的接口 schema 和只读目录响应。接口演进时优先重新核对这些事实源。
