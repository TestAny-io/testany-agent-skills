# 使用反馈：GitHub 链接与更新差异

## 需求与界面（2026-09-15）

- 关联 Git 来源时可直接粘贴 GitHub 仓库的浏览器目录链接，无需拆分仓库和子目录。保留分支/标签覆盖输入；非 GitHub 仓库可展开高级选项填写子目录。安装技能使用相同规则，预览展示实际仓库、ref、子目录和 commit。
- 更新及来源关联预览保留文件变更清单，增加默认折叠的“查看代码差异”。展开后按文件加载带旧/新行号、增删颜色、上下文的 unified diff；文件可分别折叠。二进制、符号链接与过大文本明确说明，不能伪装成无变化。
- 移除侧栏底部本地运行宣传文案，将产品署名改为用户指定的 `A Testany Product`，保留版本信息。

## 工程设计

GitHub tree URL 在服务端归一化；clone 后按真实 Git refs 解析包含斜杠的分支/标签，支持 commit 链接。显式 ref 覆盖下载版本，但不改变 URL 指定的子目录；歧义和非法链接返回可解释错误。保存规范仓库、子目录、ref 和实际 commit，以便后续定时更新。原仓库 URL、SSH 来源、本机路径和旧记录继续兼容。

新增 `preview.diff` 请求（previewId、path），按现有 token/origin 和互斥规则处理。仅允许读取尚未过期的更新/关联预览中的变化文件，再次核实安装基线、目录边界和暂存内容。按需生成 diff，不将源码正文写入清单、更新计划或操作历史。采用固定版本 jsdiff 的结构化 patch，限制单文件字节、计算时间和返回行数；React 以纯文本渲染文件内容。查看差异不消费预览、不应用更新。

## 验证计划

覆盖示例 URL、默认/显式 ref、包含斜杠的 ref、commit、非法来源和旧格式；真实公开 GitHub 链接预览；diff 的增删改、行号、换行、Unicode、HTML 文本、二进制、符号链接、大小边界、过期或被篡改预览和路径越界。浏览器验证三语言、深浅色与窄屏、默认折叠及展开行为、来源关联到更新的完整流程、底部署名。测试全部使用隔离目录，不修改用户真实安装。
