### 3. 规则是否自洽

- **第 1 步与第 3 步一致。** DEC-SDX-021、第 683 行与 5.4 新字段行都写“转交时”原样转发、以数据目录为工作目录；5.4 义务行对“方案 B 第 1、3 步”使用同一参数形式（`start`，可能带转发来的 `--project`，数据目录为工作目录）。第 2 步不调用任何启动脚本，不涉及转发。
- **“③～⑤ 时复用运行实例不改变项目；①② 时与 0.11.x 自身入口收到显式 `--project` 相同”：自洽，但依据的是 0.11.x 实际收到了什么，而不是项目的原始来源。**
  - 0.10.2 原生入口在调用前已把环境变量或 `project.json` 解析成 `--project`。所以经 0.10.2 原生入口进入的值，到 0.11.x 时都是①（F 除外）。
  - 后果：实例正在运行、又经第 1 步（或 0.10.2 直接调用 Codex 侧 0.11.x 的 L1 路径）进入时，来自 `project.json` 的值按显式项目处理，实例可能被切到该项目。这与 L1 路径在 v1.0 中的行为一致，也与 0.10.2 自身的语义一致（`launch.mjs:157`：解析出的项目与运行实例不同就重启），不是新问题。
  - 冷启动不受影响。
  - 这些情形的期望结果需要在 API 契约的期望结果表中写明（R9-P2-03 第 3 项）。
- **第 2 步不使用收到的 `--project`。** 实例运行中时，0.10.3 技能入口显式指定的项目不会生效（例如 Claude 侧仍是 0.10.3、Codex 侧 0.11.x 实例在运行）。这一表现 v1.0 已存在，第 8 轮也没有指出（评审者遗漏）。第 1344 行“过渡期用户指定的项目在冷启动时同样生效，不再需要登记新的已知表现”只对冷启动成立。见 R9-P2-03 第 3 项。
