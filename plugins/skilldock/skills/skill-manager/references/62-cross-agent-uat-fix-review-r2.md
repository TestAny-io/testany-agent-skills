  - 实现只接受 `source` 为字符串的项（`claude-catalog.mjs:110` 的 `marketShape`），仓库等取自顶层 `item.repo || item.url || item.path`（`:333`）；单元测试的命令行替身输出 `[{"name":"m","source":"github","repo":"o/m"}]`（`tests/claude-catalog.test.mjs:164`）。
  - 隔离环境中真实命令行的样本（scratchpad `verify/v13-lab/v13-result.json` 第 2 步，只看结构）：`[{"name":"labmkt","source":"directory","path":…,"installLocation":…}]`。
- **试跑**（把 `61` 中的过滤原样取出，喂合成输入）：
  - 扁平、顶层带 `"ref":"feature/skilldock-0.11-cross-agent"` → 输出 `{"name":"testany-agent-skills","ref":null}`；
  - 扁平、没有 `ref` → 同样输出 `{"name":"testany-agent-skills","ref":null}`；
  - 只有嵌套形状才会读出 `ref`。
- **影响**：第 8 节在合并到 `main` 之后执行，用来确认 Claude 中的 marketplace 已改回跟随 `main`。这条检查不论是否切换成功都会通过，测试者会跳过第 3 项（移除并重新添加）。若实际没有就地切换，Claude 一侧会继续跟随开发分支，分支停止更新或删除后，Claude 中 SkillDock 与 testany-eng 都收不到更新，且没有明显提示。输出里同时缺了 `source` 与 `repo`，细心的人能看出异常，但说明只要求看 `ref`。
- **不确定的部分**：命令行输出中 github 类型的 marketplace 是否带 `ref`、放在哪个键，本轮无法核实（不得运行真实命令行或读取真实 `~/.claude`）。无论哪种情况，现在的过滤都读不出它。
- **建议**（在执行第 8 节之前修订 `61`）：
  1. 过滤兼容两种形状，并列出该项有哪些键（只列键名），让“没有 ref 字段”与“ref 为空”可以区分，例如打印 `{name, type: typeof m.source === "string" ? m.source : m.source?.source, repo: m.repo ?? m.source?.repo, ref: m.ref ?? m.source?.ref ?? null, keys: Object.keys(m)}`。仍不打印 `url`（私有仓库的 URL 可能带凭证）。
  2. 写明判定方法：`keys` 中既没有 `ref`、`source` 又不是对象时，说明命令行输出不含 ref，不能据此判断。此时改为请用户在 Plugins 页看该 marketplace 显示的来源，或只读回 `~/.claude/plugins/known_marketplaces.json` 中 `testany-agent-skills` 一项 `source` 对象的 `source`、`repo`、`ref` 三个键（不打印文件其余内容，符合第 2 节的边界）。
  3. 第 3 节“`marketplace list --json` 中该项的 source 字段，只看仓库与 ref”沿用了同一假设。第一部分已经做完，这里不必重做，改写时一并更正即可。

### UF2-P3-03 `61` 第 7 节第 5 项的几处说明

1. **核对放在停止之后**：第 116～117 行的同一个代码块先 `echo "$D"`，紧接着就运行 `launch.sh stop`；“`D` 为空或目录名不是新版本的摘要时停下”写在代码块之后（第 120 行），实际执行时实例已经停了。`D` 为空时 `stop` 只会报找不到脚本，无害；`D` 指向旧版本目录时，实例仍会被停止，后面又要求停下，用户会处在实例已停、核对未做的状态。建议拆成两步：先只取并打印 `D`、核对目录名，确认后再单独运行 `stop`。
2. **“改回 `main` 后消失”不准确**（第 123 行）：改回 `main` 后 Codex 一侧仍是 0.11.0，同版本不重启实例。若此前实例已由修复前的 Codex 原生入口全新启动，提示会继续经复用与隐式重启带下去，直到由修复后的启动器全新启动、在界面中切换项目或自更新为止。第 112 行“复用或隐式重启都不会消失”已经说对了，第 4 小项与之矛盾。建议改为“改回 `main` 后，实例下一次由新启动器全新启动（或在界面中切换项目）时消失”。
3. **（说明，不要求改）** 第 2 小项写“由 Claude 这份修复后的启动器全新启动”。实际上任何带有效 `--project` 的全新启动都会清掉旧提示，修复前的启动器也一样。所以这一步验证的是“旧提示跟着实例”这一解释，不是修复后的回退路径本身。回退路径已由定向测试与兼容矩阵 N-03（真实 0.11）覆盖。若想在真机上也覆盖，可在停止实例后，用 Claude 这份启动器在固定子目录中执行一次 `start --project <数据目录>/compat/legacy-project`，确认 stderr 有跳过说明、页面顶部没有提示。
