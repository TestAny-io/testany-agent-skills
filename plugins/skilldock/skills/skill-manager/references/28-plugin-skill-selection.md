# 插件安装前的技能清单与启用选择

版本：0.6.0。包含安装前技能选择这一新增兼容功能，按 SemVer 从 0.5.0 递增 minor；同时修复逐技能开关。

## 问题与产品需求

Marketplace 安装确认页此前直接使用目录记录，未读取插件技能。本地/Git 预览只有一行技能名称，无法查看用途、区分同名项或选择启用范围。另一个相关问题是技能库中点击插件技能开关会切换整个插件。

本轮以“整包安装，选择启用”实现：

1. Marketplace、本地和 Git 三种入口均在确认前读取技能名称、description 和相对路径；缺失/非法来源明确报错。
2. 默认勾选全部，提供搜索、全选和全不选。搜索只改变显示，不能改变隐藏项的选择；相同名称按路径区分。
3. 明示安装总数与启用数，以及未勾选技能仍保留文件但禁用。MCP、Hooks 等其他组件单独列出，技能选择不会移除它们。
4. 安装后技能开关仅修改本项。插件总开关仍作用于整个插件；总开关关闭时先启用插件再调整单项。
5. SkillDock 更新保留逐项选择，新增技能默认禁用。退出或重启服务不丢失选择。

Codex 原生 CLI 公开的 `plugin add` 以完整插件为单位，没有部分技能安装参数；官方文档支持通过 `[[skills.config]]` 的绝对 `SKILL.md` 路径禁用技能。此轮未提取独立技能，也不重写插件包内容或依赖关系。来源：[CLI 命令](https://learn.chatgpt.com/docs/developer-commands#codex-plugin)、[技能开关](https://learn.chatgpt.com/docs/build-skills#enable-or-disable-local-codex-skills)。本机真实 CLI/App Server 另外验证了插件内逐技能配置的有效性。

## 界面设计

保留来源 → 预览与安装两步流程。预览使用紧凑的插件摘要，随后显示可搜索的技能列表：勾选框、名称、用途和相对目录。标题显示“安装 N 项 · 启用 M 项”；较长清单滚动显示，弹窗底部确认按钮固定可见。中、英、日及浅深色同步。

Marketplace 点击预览时显示读取状态；失败后留在来源页，给出实际错误，不显示可确认安装的空清单。真正零技能的插件明确显示“没有附带技能”，仍列出其他组件。

## 工程边界

- `plugin-contents.mjs` 共用现有默认/声明发现规则，递归读取到 SKILL.md 为止；按 SKILL.md 真实路径去重，但不按名称合并。声明的额外目录保留，越界/悬空链接和无效 metadata 失败，目录遍历有上限。单项开关、安装和更新配置均使用真实路径，包括 CODEX_HOME 自身为链接的情况；避免仅禁用别名而原生加载仍启用。
- 新增 `plugin.previewMarketplace`；市场预览绑定模式、插件、来源目录身份、版本、清单及技能内容摘要，30 分钟有效。安装前重新读取核对；请求中的选择必须来自预览，不能传任意文件路径。直接安装沿用原暂存内容核验。
- 安装动作可接收 `enabledSkills` 相对路径数组；空数组表示整包安装但不启用技能。未传选择的旧调用保持兼容。无法证明共享组件到缓存的映射时只展示清单，不提供选择。
- 多项技能设置作为一次经过语义校验、备份和并发检查的 TOML 修改写入；不修改无关配置或插件文件。选择在原生安装前写入确定的目标路径，使新加载的技能遵循选择。
- 选择按插件 ID 和包内路径存入 SkillDock registry；手动/定时更新将选择映射到新版本的缓存路径。外部工具更换版本后，在下一次 SkillDock 检查时重建配置；不承诺外部更新发生瞬间或已运行会话即时生效。
- 原生 CLI 返回失败或安装终态不确定时，保留已写入的选择与来源记录并报告错误，不假称安装已回滚。安装、配置、更新和 API 写入仍使用既有鉴权与跨进程操作锁。

## 验证

测试仅使用临时来源、CODEX_HOME、项目与运行数据，不触碰本机已有安装或远程种子用户环境。

- Node 完整回归 170 / 170 通过（0.6.0 提交前）：涵盖三个来源的共用发现、嵌套及额外声明目录、同名不同路径、部分选择、全不选、选择伪造、过期预览、内容变化、单项开关、内部链接别名、定时更新、新技能默认关闭、重启和外部同步后的恢复。新增针对旧安装的回归：原本全部启用时禁用一项，其他技能及插件总开关仍启用。
- 浏览器完整回归 72 / 72 通过；新增 22 项技能清单的三语言 × 两主题选择/安装读回，本地/Git 取消，以及读取失败不显示空确认页。进一步压缩摘要并固定弹窗按钮后，相关 19 / 19 用例复测通过，含确认按钮完整位于视口内的断言。
- `tests/plugin-skills-native-smoke.mjs` 在真实 Codex CLI 分别执行 Marketplace 和直接来源安装，App Server 的 `skills/list` 读回一项启用、一项禁用；再启用 beta 并禁用 alpha，原生读回仅 beta 启用且插件总开关未关闭。恢复选择后更新，仅原选中项启用，未选项和新增项均禁用。另验证内部链接别名和符号链接形式的 CODEX_HOME。临时配置与进程随后清理。
- 生产构建、TypeScript 和对应源码包生成通过；仓库发现检查通过（35 项技能，静态检查，不代表所有宿主验证）。本地截图与日志保存在 ignored `output/skilldock-plugin-preview/`。

### 本机宿主验证发现的已有兼容边界

当前真实 Codex CLI 在缓存插件时不保留包内目录符号链接。包含这类链接的测试插件，逐技能选择已按真实路径正确生效；但更新后缓存与原包结构不完全相同，因此既有完整包校验仍返回 `READBACK_FAILED`，不能报更新成功。本轮保留该保护，没有通过忽略链接差异来放宽更新成功条件。原始失败证据另存 `native-alias-investigation.log`；原生测试的链接分支明确断言这个失败，不能将其与普通目录插件的更新成功混为一谈。发布方应优先分发实际目录，宿主符号链接兼容需要另行处理。

## UAT

安装插件 → Marketplace 选中一个含多个技能的插件 → 查看用途与目录 → 只勾选两项 → 确认安装。技能库应显示完整包的技能，但只有选中项启用。分别验证搜索后选择不丢失、取消不安装，以及关闭/开启插件总开关后仍保留选择。旧版误关整个插件的用户升级后，需要先在 Plugins 页重新启用插件，再禁用目标技能；不能从旧总开关推断原意，因此不自动更改其状态。
