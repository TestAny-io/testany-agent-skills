## 2 官方应用目录这处改动的判定

`server/app-directory.mjs:65-91`。

**实现与注释一致，主要目的达到了。** 实测（替身）：进程的第一次读取要等；过期后立即返回上一次的结果，后面只发起一次读取，多少个调用方都共用它；后面那次读完，下一次调用拿到新结果。

逐项回答：

| 问题 | 判定 |
|---|---|
| 调用方会不会拿到不该拿到的旧结果 | **会拿到旧的，但只用于显示和状态，不用于决定写什么。** 清单读取（`cli.mjs:164`）用它补名称、图标、安装入口、`connected`、`canInstall`；安装预览另读 `app/read` 核对应用身份与安装入口；安装本身由 Codex 命令行决定。两点见 C13-P3-02：旧结果的年龄没有上限；安装后的读回（`service.mjs:1708`）里“是否已连接”可能来自旧结果 |
| 后面那次读取失败时是否如注释所说 | **是（实测）。** 触发它的那次调用已经拿到旧结果；此后一分钟内直接报上一次的错（强制读取会再试一次）；一分钟后的那一次要等，仍失败就再报错一分钟；成功后恢复，之后过期时又先给旧结果 |
| 未处理的 rejection | **没有（实测）。** 后面那次读取失败时没有未处理的 rejection；去掉那个空的 `catch` 用例会失败（变异 A4 被杀） |
| 强制刷新遇到在途的非强制读取时共用它 | **比原来容易发生得多，后果的性质没有变。** 见 C13-P3-01 |
| 后台任务等短命进程 | **基本不受影响。** 每个进程的第一次读取照旧要等。进程活过 10 分钟、又在结束前读过一次时，会留下一个在途读取：实测（替身进程）进程要等它结束才退出——读取 4 秒时在 4.8 秒退出，读取不返回时在 45 秒超时后退出，没有留下子进程。后台任务在这之前已经释放了锁（推断，代码） |

另一点没有验证：后面那次读取现在会与用户随后的操作并行（例如页面一打开就点安装或更新），也就是一个 `codex app-server` 进程与一条 Codex 写命令同时运行。原来页面在等这次读取时，这种并行少得多。Codex 是否介意，未做。

## 4 新发现

### C13-P3-01 目录过期时，“核对连接状态”的强制刷新搭上了刚发起的非强制读取（可留到下一版，建议尽早）

- **位置**：`server/app-directory.mjs:72`、`:76`；`server/service.mjs:1488-1490`。
- **原因**：`plugin.connectionStatus` 先读一次清单，再强制刷新。目录已过期时，这次改动让前一步立即返回旧结果、在后面发起一次非强制读取；强制刷新紧跟着到，发现有在途读取就共用它（`:76`，原有逻辑）。结果是 `forceRefetch: true` 根本没有发出去。原来前一步要等自己的读取结束，强制刷新到的时候没有在途读取，是真的强制。
- **现象（实测，替身；每种情形都拿 `ce1ce72` 的模块并排跑）**。替身的回答方式是：不强制时按它上一次取到的回答，强制时才重新取——这是假设，用来看 SkillDock 发了什么请求：

  | 情形 | `ce1ce72` 发出的读取 | `3747845` 发出的读取 | `3747845` 的结果 |
  |---|---|---|---|
  | 目录已过期，15 秒以上没有读过清单，直接核对连接 | 非强制，再强制 | **只有非强制** | 第一次“未连接”，再点一次（强制）“已连接” |
  | 目录已过期，页面先读一次清单，紧接着核对连接 | 非强制（页面等它），再强制 | **只有非强制** | 同上 |
  | 目录没有过期 | 强制 | 强制 | 一致 |

- **影响**：第一种情形不需要碰巧——离上一次读取超过 10 分钟再来核对连接，就是这条路。真实的 Codex 对不强制的读取是否会给出它缓存的“是否已连接”，没有验证；若会，用户授权之后第一次核对会看到“尚未连接”，再点一次才对。若不会，没有可见后果。
- **测试**：没有用例覆盖“有读取在途时来了强制读取”。把它改成不共用（A7），或把后面那次读取改成强制的（A8），全部用例照样通过。

### C13-P3-02 旧结果的年龄没有上限；安装后的读回可能用到它（可留到下一版）

- **现象（实测，替身）**：一天没有读取之后，第一次调用拿到的是一天前的结果，后面那次读完，下一次调用才是新的。HLD 7.1 写的是“可能是十几分钟前的”。
- **影响**：服务长时间开着、页面隔了很久再打开时，官方目录插件的名称、图标、“是否已连接”、“能否安装”先按旧的显示；页面不会自己再读一次（41 UI-19 已登记），要等用户刷新或做下一个操作。安装官方目录插件之后的读回（`service.mjs:1708`）同样可能拿到旧的“是否已连接”，对话框里那句“应用连接可用”或“请继续完成授权”就按旧状态说；原来这里过期时会等一次新的读取。
- **不受影响的**：安装前对应用身份与安装入口的核对（另读详情）。
