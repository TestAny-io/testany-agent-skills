# SkillDock：统一技能库与插件操作、直接安装单插件

版本：0.5.0。新增兼容功能，按 SemVer 从 0.4.2 递增 minor；本地验证完成，系统文件夹对话框待 UAT。

## 产品范围

本轮响应种子反馈：插件安装原本藏在 Marketplace 的可发现清单里，Skills / Plugins 的布局和操作顺序不一致。需要在插件页提供明确安装入口，同时允许直接安装一个插件，而不让用户先配置 Marketplace。

用户最终决定暂缓“创建项目”：不创建新文件夹，不向 Codex 侧栏写入项目。保留已提出的已有项目下拉选择，支持浏览本地文件夹和手动路径回退。

验收目标：

1. Skills / Plugins 的右上角均提供安装按钮；统计筛选、搜索、标签、卡片/列表、详情、分页遵循同一模式。
2. 安装顺序均为选择来源 → 预览 → 确认；取消预览不安装。插件另有 Marketplace 来源选择，添加 Marketplace 后返回安装窗口。
3. 单插件支持本地目录、Git 仓库与 GitHub 目录链接，预览实际名称、版本、组件、技能及重复名称；仅安装选定插件，不扩大为整个仓库。
4. 原来源、子目录、ref 和 commit 可回看；插件可继续检查、预览 diff、手动或定时更新。已有本地变化、同版本变化与目录替换保护保持有效。
5. 项目下拉显示 Codex 已保存项目、最近选择和当前目录；按真实路径去重，缺失目录禁用。选择保存后更改扫描范围，显式启动参数仍优先。
6. 中、英、日及浅深色和窄窗口均可操作。

## 交互设计

两页共用统计按钮、视图切换、分页及安装对话框。卡片主体进入详情，底部保留启用开关，标签入口位置一致。插件详情显示版本、来源、身份和附带技能，提供更新与卸载。对未安装插件保留就近安装按钮。

插件安装提供本地目录、Git 仓库和 Marketplace 三种来源。Git 沿用单个 GitHub 浏览器目录链接的解析及私仓凭据说明；无需手工拆分链接。Marketplace 展示搜索、来源筛选、已安装和受管理限制的状态，避免无解释的不可点击项。

项目使用下拉直接切换已有目录。“选择本地文件夹”打开选择窗口，macOS 可调用文件夹选择器；高级入口提供绝对路径。取消选择不改变当前项目，非法目录保留原状态，不出现“新建项目”入口。

## 工程设计

- `LibraryUI.tsx`、`InstallDialog.tsx`、`ProjectControls.tsx` 抽取共用交互；旧重复安装和项目输入对话框移除。
- 新增 action：`plugin.previewInstall`、`plugin.installSource`、`project.chooseDirectory`；沿用 loopback/Origin、会话令牌、严格字段和跨进程操作锁。
- 单插件预览调用已有 Git URL/ref 解析、凭据环境和文件边界检查，将确认内容放入限时 staging。安装前重新核实本地源和 staging 摘要。
- 当前实测 Codex CLI `plugin add` 使用 `PLUGIN@MARKETPLACE`。SkillDock 在自身数据目录 `local/direct-plugins/<来源摘要>` 生成仅含一个插件的 `.agents/plugins/marketplace.json`，再调用原生 marketplace add/plugin add，并读回安装版本、启用状态和整个缓存内容。
- 用户无需手工登记市场。自动登记来源显示插件名称，机器身份仍保留稳定来源摘要。原 Git 地址、目录、ref、commit 与源副本摘要保存在 registry；未确认的 CLI 结果保留来源记录，以便刷新核实。
- 单插件要求唯一支持的 plugin.json 且有有效 name/version，版本仅由插件清单定义。默认/显式技能组件路径复用现有发现逻辑；越界或悬空链接失败，不复制外部组件。沿用 32 MB、3000 文件/链接限制。
- 更新先把原来源复制到受管理的来源目录，再走已有 Codex 包级更新、差异、基线和计划绑定逻辑。私仓沿用本机 Git 凭据，不把 token 写进 URL/registry；本地来源不会自动 git pull。
- Codex 项目目录是只读兼容读取：当前 `.codex-global-state.json` 的 `local-projects` 优先，旧版回退到 `electron-saved-workspace-roots`。解析失败说明原因，不篡改 Codex 状态文件。最近目录仅写入 SkillDock 自身 `project.json`。
- macOS 文件夹选择器使用固定 AppleScript 和参数数组，用户路径不会拼接成脚本。其他平台提供手动输入回退。

## 验证与 UAT

所有安装与更新验证使用独立临时配置、来源和缓存，不涉及种子用户的远程环境，也不修改本机现有插件安装。

自动化覆盖：单插件预览不安装、仅安装所选包、来源元数据、卸载重装、新版 diff/更新、禁用状态保留、Git 定时更新及服务重启后续跑、缺失/多重清单、来源变化与越界链接；项目新旧元数据格式、路径去重、缺失目录、选择持久化、取消、鉴权与固定 argv。现有页面生命周期和项目选择浏览器测试随新入口调整。

实际 CLI 使用 macOS 桌面应用内的 Codex CLI，在独立 CODEX_HOME 验证单插件安装、包更新、Marketplace 安装，并核对真实安装清单和缓存摘要。浏览器另外走完本地单插件、Marketplace 插件和单技能的预览/确认，以及插件开关和已有项目切换。

系统文件夹对话框由可注入适配器验证调用与取消行为，浏览器测试使用可控选择结果；真实桌面文件夹选择体验留给 UAT。新建项目和 Codex 侧栏创建不在本轮交付范围。

待用户 UAT：

1. 在 Skills / Plugins 间切换，比较搜索、标签、视图、详情、安装和移除的位置与步骤。
2. 从本地插件目录或 GitHub 插件目录链接安装，确认只有目标插件；检查详情中的原来源，再在 Updates 中选择它。
3. 从安装窗口进入 Marketplace，搜索插件；如需添加来源，完成后确认回到安装列表。
4. 从项目下拉选择现有项目，再通过文件夹选择器切换一个已有目录；刷新后核对路径与项目技能。
