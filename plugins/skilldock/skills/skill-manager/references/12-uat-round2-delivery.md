## 需求与设计决定

1. 界面使用小时。原1440分钟即24小时，并不是短周期。预设1、24、168小时只显示一个选择框；自定义才出现标有小时的数字输入。范围0.25–168小时，兼容原15分钟–7天周期；支持可换算成整数分钟的小数，拒绝隐式四舍五入。
2. 已有计划的实际周期不能变化。共享API、后端调度和持久化仍使用`intervalMinutes`；打开表单时转成小时字符串，仅保存时校验并换回整数分钟。61分钟等非整小时值也必须无损往返。三语计划摘要与保存提示使用小时。
3. 关联窗口在表单前展示“已检测到的来源信息”：来源地址、来源内目录、分支/标签、commit。有Git证据或已保存来源则展示并预填；缺失字段写“未记录”，同时解释原因。
4. 不能把当前Git HEAD当作历史安装commit，也不能以技能名、内容相似或当前仓库冒充旧安装来源。无origin的真实Git工作区仍可展示当前HEAD、分支及相对目录；本地来源的有效子目录不能被错误隐藏。

本轮实际调查见 [来源元数据事实记录](11-source-metadata-findings.md)。本机27个独立技能为普通目录，没有可核实安装来源记录。现装官方安装脚本复制选定技能后清理临时仓库，没有持久化repo/ref/subpath/resolved commit。当前后端已读Git及SkillDock记录，没有发现可补读的可靠登记表，因此不新增虚构的metadataadapter。

[官方 Build skills](https://learn.chatgpt.com/docs/build-skills) 描述名称、说明及可选的界面/依赖元数据，没有要求保存原始安装commit；该文档与本机脚本事实各自证明其范围。
