# TeamDesk 0.2.0

**在现有 Codex 上组织 AI 员工，用本地工作台查看进展、交接、证据与人类决定。**

支持 macOS、32 位在职员工、任意部门/岗位/技能流程。员工继续在 Codex 原生任务中使用现有 skills/plugins；工作台只保存业务数据和 metadata。

## 种子测试版

0.2.0 是种子测试修正版，修复独立下载入口在 macOS 临时目录下静默退出的问题。包含此前 MVP 全部功能，以及统一安装入口：依赖检查 → 原生插件安装 → 启动图标创建与核验。连接恢复、完整回执链和可回放的部门/员工协作视图也已包含。

当前面向 macOS Codex Desktop。共享接入仍依赖 Codex 的实验接口；另一台 Mac、Intel Mac、较早 macOS 和完整冷启动仍需种子用户实测，不能将本机隔离安装当成跨机器认证。具体已测范围见 [验证记录](docs/VERIFICATION.md)，反馈路径见 [种子测试指南](docs/SEED-TESTING.md)。

版本规则：本地迭代 patch +1，合并远程 main 时 minor +1、patch 归零，major 由用户决定；插件 manifest 是版本唯一权威。

## 已实现能力

- 提交即派发到桌面实际使用的共享 App Server，不再依赖接入 thread 或模型定时检查。
- FIFO 使用 Codex 原生队列；steer 校验业务和当前轮次。多名员工独立接收输入。
- 请求先持久化，再发给 Codex；重复点击复用同一请求。断线后核对原生队列与输入 ID，结果不确定时不重发。
- 共享 hook 可在工作台审查与信任。已有定义复用，新增员工自动探测；信任状态与实际记账就绪分开。
- 原生问题、问题回答、待审批操作和回执按员工/轮次/请求 ID 归属；本机事件推送更新页面。
- 升级保留原有员工、任务、摘要、证据和验收。旧待派任务保留待核对，自动化不恢复。
- 指定协作者必须实际参与。技能能力说明来自已绑定 SKILL.md 的 frontmatter description；派发保留快照。员工可直接继续分工，每次结果由交接发起方处理，负责人整合最终交付；界面分别展示交接、结果和处理证据。

- 部门由名称、职责、成员和可选交接联系人组成；原分组自动迁移，未确认职责留空。同部门查询技能描述，跨部门只查询职责、岗位与联系信息。员工最多属于一个部门，也可未分配；移出与转部门不会重建会话或打断任务。部门可删除/恢复，历史资料与工作记录保留。
- 团队资料支持编辑草案、确认发布、删除及恢复为草案，并保留历史版本；员工只查询团队及本部门的生效内容。保存新草案保留前一生效版本。
- 每次原生输入仅包含本次请求、任务摘要与查询入口；员工按需查询组织、技能、规则、SOP、目标及决定。
- 验收通过与退回都通知负责人。通过通知只记确认回执，不改变已验收交付，也不自动启动下一项任务。
- 部门职责、员工工作说明提供就地 AI 撰写：说明意图、必要澄清、预览建议与修改对比，继续完善后由人类采用到表单，再正常保存。助手按需查询组织、技能描述和生效资料，不占员工名额。
- 新任务的目标与完成标准由同一 AI 助手联动整理，参考已选负责人/协作者能力及相关生效资料；可以选择回填一个或两个字段，原“保存并交给 Codex”才创建与派发业务。切换负责人、协作者或修改原文后需重新生成。工作约定／SOP 暂不接入 AI 撰写。

## 安装与启动

在 macOS 的「终端」复制运行以下整段命令，无需先 clone 或配置 Codex CLI 的 PATH：

```sh
curl -fL https://raw.githubusercontent.com/TestAny-io/testany-agent-skills/main/install-teamdesk.sh -o install-teamdesk.sh &&
sh install-teamdesk.sh
```

安装程序会：

1. 查找 Codex Desktop、Safari 和可用 Node，检查版本、Git 与编译工具。
2. 通过 Codex 原生命令添加/更新 GitHub main marketplace，只安装 `teamdesk` 插件并读回启用状态。
3. 生成 `~/Applications/TeamDesk.app` 及桌面链接，核验应用版本和本地签名，然后打开图标。

**依赖**：macOS 13+，已安装并正常打开过的 Codex Desktop（内置 CLI 数字基线 ≥0.155.0，含同基线预发布版本），Node.js ≥22.13 且包含 `node:sqlite`，Xcode Command Line Tools。优先复用 Codex 内置 Node；若缺少编译工具，按提示执行 `xcode-select --install`，安装完成后重跑同一命令。无需 `npm install` 或单独模型 API key。日常点击图标不需要编译器。

若 Codex 正按普通方式运行，安装不会中断它；首次使用共享接入需要你正常退出 Codex 后再点 TeamDesk 图标。首次 hook 信任仍由你在团队设置中审查、确认，不由安装程序代替。

已有本仓库 clone 时，在仓库根目录执行 `sh ./install-teamdesk.sh`，会使用本地 clone。若同名 marketplace 已绑定另一来源，安装器会停止并说明冲突，不静默更换其他插件的来源。

可选参数：

```sh
sh install-teamdesk.sh --check       # 只检查依赖
sh install-teamdesk.sh --no-open     # 安装完成后不打开图标
```

失败会显示阶段；修复依赖后可重跑。已有插件、图标和业务数据会保留；已安装较新版本时不降级。从其他 marketplace 安装过 TeamDesk 时，先在 Codex 中明确保留的来源，不重复安装两份。自定义 `TEAMDESK_NODE` 或 `CODEX_HOME` 会写入本机图标配置，以便 Finder 启动时使用同一配置。

手动管理本地服务：在已安装插件目录执行 `sh skills/team-workspace/scripts/launch.sh start`、`status` 或 `stop`。默认地址为 http://127.0.0.1:4322；`TEAMDESK_PORT` 可指定端口。不能部署公网；启动器不结束占用端口的其他服务。

[安装实现与边界](docs/INSTALLATION.md)。随插件包含 MIT 许可的 js-yaml，来源及许可证见 skills/team-workspace/assets/app/vendor。

## 一键启动 Codex Desktop 与 Safari 工作台

统一安装流程已创建图标。仅需重新创建已安装插件的图标时，在插件目录运行：

    sh skills/team-workspace/scripts/launch.sh install-icon

生成 `~/Applications/TeamDesk.app` 和桌面上的同名快捷图标。双击桌面图标；也可以自行拖到 Dock，之后单击启动。

1. 自动启动或复用本地 TeamDesk 服务。
2. Codex 未运行时，以共享接入方式启动已有 Codex Desktop；已共享时核验并复用。
3. 明确使用 Safari 打开工作台，不受默认浏览器设置影响。

若 Codex 已按普通方式运行，图标会在 Safari 打开团队设置，并提示先正常退出 Codex、再点击图标；不会强制结束员工任务。打开页面、Codex 窗口请求与共享连接分别核验；Codex 启动失败仍打开已可用的工作台设置页，启动阶段与错误保存到数据目录的 launcher.log。

图标每次通过 macOS 应用注册和本机插件安装文件查找路径，不调用 codex plugin list，也不写死 TeamDesk 缓存版本。缺少、损坏或存在多个安装目录时给出明确错误。原生插件启用状态、工具权限和 hook 信任仍由 Codex 配置管理；离线定位本身不修改这些设置。新版本插件替换服务时，只在核对进程路径、PID 与数据目录后停止旧 TeamDesk 服务，保留数据及自定义端口。启动设置只作用于本次 Codex 进程，不修改 Dock 原图标、全局环境或登录项。CLI 基线仍为 ≥0.155.0；未来 Codex 接口变化仍可能需要调整适配器。

## 一次接入，所有员工复用

1. 打开「团队设置」。已有共享连接会自动核验；未共享时，先正常退出 Codex，再点击 TeamDesk 图标，或点「以共享接入启动 Codex」。不强行中断任务、不改全局启动项。以后直接打开 Codex 可恢复默认启动方式。
2. 「审查共享 hook」展示原生配置、命令、脚本和审查摘要。只有真实人类确认才写入当前定义的原生信任；已信任定义直接复用。管理员策略不覆盖。
3. 新建或绑定员工。配置来自共享插件，无需逐人添加 hook 文件或项目。自动入职探测产生当前版本的原生记账回执后显示就绪。
4. 提交业务。按需派发进入原生队列或当前业务轮次；负责人按 skill 流程开展工作。

原生问题保留 questionItemId；即使尚未建业务，也可准确答回原提问。私密问题和已失效的原生回调在 Codex 中处理。可完整显示的普通命令审批提供原生允许的本次选择；文件修改、额外权限或网络范围等复杂审批转回 Codex 审查。工作台不代替用户申请持久权限。

## 运行与恢复

- 数据目录：~/Library/Application Support/TestAny/TeamDesk。SQLite WAL 持久化业务输入、员工、绑定、摘要、回执、决定与验收；artifacts/ 保存明确提交的产物。
- 服务停启保留数据；停止 TeamDesk 不会停止原生员工。共享适配器由桌面进程拥有，只有退出桌面才随之结束。
- 连接离线或 hook 未信任时，输入保存在本地。连接重试只重连传输，不调用模型。
- 升级前停止工作台服务并制作 SQLite 一致性备份，再安装新插件、从新路径启动。旧 pending 操作迁移为暂停，leased/sending 迁移为不确定；不自动补发旧操作。
- 明确失败可恢复派发；结果不确定只核对回执，不把“未找到”当作“未执行”。新建结果不确定时，先从原生任务列表绑定已创建任务。
- 旧版 TeamDesk heartbeat 保持暂停，不再使用。删除自动化仍需用户明确要求。
- 换绑/归档不撤回已经到达原生任务的输入。取消业务通过有明确业务目标的补充输入交给负责人。
- 导出 metadata 便于检查，不是完整数据库恢复包。备份应使用 SQLite 在线 backup，或服务与员工记账停止后复制数据库及其 WAL/SHM。

## 边界

同一 macOS 用户及其本地进程为信任边界。部门可见性用于组织信息和减少上下文，不是操作系统文件隔离；同用户进程仍可能访问本地文件。GUI 只提供受限业务接口，无任意原生 RPC 或配置编辑入口。页面校验 Host、Origin、CSRF 令牌和幂等编号。原生 WebSocket 拒绝外站 Origin。

原生线程标题只取显示名称 name；不以 first_user_message/preview 充当标题。事件白名单保存时间、来源、任务/轮次、工具名、目标和路由 ID。为人类决策明确保留结构化问题、回答和待审批命令；普通对话、思考过程、完整工具输出不入库。工作台不渲染完整会话。

共享传输、原生队列和本地日志适配依赖 Codex 版本，仍是实验接口。本版不承诺其他版本、远程主机、其他操作系统或 32 位员工同时达到固定吞吐。低于最低版本或版本无法识别时拒绝接入；更新版本继续实际握手，连接或原生操作失败时显示具体原因。
