# TeamDesk 一次安装与种子发布

## 目标与入口

当前发布版本 0.3.0（本次最低系统版本修复阶段为 0.2.1；首次发布 0.1.0 的本地开发阶段为 0.0.14；下载路径修复阶段为 0.1.1）。macOS 用户运行仓库根目录的 `install-teamdesk.sh`，依次完成依赖检查、Codex 原生插件安装、启动图标创建和安装核验。下载单个脚本时，入口先下载 GitHub main 的源码；从 clone 运行时使用该 clone。`--check` 只检查依赖，`--no-open` 安装后不打开图标。

## 实现约定

1. 仅 macOS 13+；通过应用注册查找 Codex Desktop 与 Safari。验证 Codex 内置 CLI 数字基线 ≥0.155.0（包含同基线预发布）及 plugin 子命令。优先使用 Codex 内置 Node，再查找本机已有 Node；要求 ≥22.13 且能加载 node:sqlite。检查 Git、Xcode Command Line Tools 和签名/图标工具。缺项给出具体修复方法，不以安装完成掩盖失败。
2. 使用原生 marketplace add/upgrade 和 plugin add；只安装 TeamDesk。已有同名 marketplace 来源不匹配、其他 marketplace 的 TeamDesk、禁用的插件或版本不一致均明确停止，不静默改源、删除安装或降级。安装进程互斥，重复运行可恢复未完成步骤。
3. 从原生返回的实际安装目录读取 manifest、入口和 hook，入口以真实文件路径识别直接执行，覆盖 macOS /var 与 /private/var 路径别名和符号链接。核对版本及缓存边界，并逐文件 SHA-256 比对本次下载/本地源码，再用该副本生成 `~/Applications/TeamDesk.app` 与桌面链接。同版本不同内容或源码/缓存不完整均停止构建。三个 Swift 程序使用明确的本机 CPU 架构和 macOS 13.0 编译目标；Info.plist 与依赖检查引用同一最低版本常量，不受编译器默认目标影响。签名并检查主程序、Codex 启动组件的 Mach-O 平台/最低系统版本/架构后，才原子替换本应用；不覆盖同名其他应用。图标保存本次选定 Node / Codex 配置目录，支持 Finder 没有 shell 环境的情况；日常仍动态查找 Codex 和插件。
4. 核验原生启用状态、图标版本与签名后，再读取安装位置中两个程序的实际最低系统版本和 CPU 架构；全部一致才报告安装完成，并将兼容性结果保存在安装回执中。默认打开图标；窗口/连接/实际 hook 触发由现有启动流程继续核验，不能由安装成功代替。原生 hook 信任仍须用户明确操作。
5. 不启动员工业务、不退出 Codex、不改模型与工具权限、不创建轮询自动化。安装不写业务数据库。失败报告完成到哪一步；可重跑，不删除已安装插件或已有数据。

## 验证与发布

覆盖依赖缺失、后续 CLI 版本、安装失败、来源冲突、缓存越界、重复运行、错误 manifest/启用状态、图标构建失败及含空格路径。在临时 CODEX_HOME 中使用真实 CLI 安装并编译/验签图标；发布后再从远程 main 下载入口执行一次全流程。更新 README、发现配置和版本 authority，仓库检查、完整回归后合并 main。私有数据、测试配置、运行日志和本机应用不提交。

真实第二台 Mac / Intel Mac / 较早 macOS 及新 Codex 版本的运行验证交由种子测试，不能用模拟或本机隔离安装冒充。
