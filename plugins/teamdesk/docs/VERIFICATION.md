# TeamDesk 工程验证

## 0.3.0 启动器最低系统版本修复

种子用户提供的诊断显示：M2/arm64、macOS 27.0，Info.plist 声明最低 13.0，但主程序及 Codex 启动组件的 Mach-O 均为 `minos 28.0`（SDK 26.2）。两个程序实际要求高于当前系统，因此 Finder 在启动前拒绝。此前 Swift 构建未传入部署目标；环境如何产生 28.0 尚未核验，修复不再依赖此默认值。

- 三个 Swift 程序显式指定本机架构及 macOS 13.0 目标；安装前后校验两个随包程序的真实平台、架构、最低版本及签名。
- 203 项自动测试通过，包含重现“plist 13.0 / 二进制较高版本”被拒绝、辅助组件不一致，以及继承 `MACOSX_DEPLOYMENT_TARGET=28.0` 时的实际编译/验签。原生辅助组件以无参数方式执行到明确校验失败，不打开 Codex、不触发员工工作。
- 本机真实隔离安装四步通过；主程序和辅助组件均为 arm64、最低 13.0。源码、安装缓存与应用版本/签名同时核验。安装回执记录兼容性检查结果。
- x86_64 两个程序交叉编译和最低版本检查通过；当前 SDK 的 Swift 兼容库出现缺少 x86_64 的链接警告，不作为 Intel 运行通过证据。第二台 Mac、较早系统与完整冷启动仍需目标机器复测。
- 本地修复版本为 0.2.1，main 发布按约定升为 0.3.0。公开安装验证见对应发布说明，不将本机测试当作种子用户已恢复。

修复增加只读任务进度投影。当前绑定、输入请求、原生轮次和业务引用匹配后，首页/列表/筛选/详情立即显示执行中；尚未生成的业务编号、名称和类别单独提示。队列中的其他业务不借用同一员工的活动状态；轮次结束只表示等待工作记录，不能自动标记业务完成。负责人记录与人类验收字段不被投影修改。

本机真实 UAT 任务验证：首页推进中 1、等待开始 0；任务筛选和详情均显示执行中，并分别提示业务信息待补齐。服务重启后仍对应原来的执行轮次，没有重新派发业务。新增 7 项回归，完整测试 56/56 通过，24 个 JavaScript 文件语法检查通过。实际浏览器核对通过。证据在忽略目录 output/teamdesk-v0.0.1/uat-status。

## 0.0.1 UAT 修复：指定协作者、技能能力说明与网状交接

原实现保存了协作者，但只要求“需要时联系”，目录也未包含已绑定技能的能力说明。现在，新任务明确保存人类指定的 requiredCollaboratorIds，与动态 participants 分开；派发消息带必须实际参与的约定及当时技能 name/description/path/SHA-256 快照。所有员工的 inbox 目录提供当前绑定技能的 description。YAML 多行、引号、缺失、读取错误分别处理，能力说明作为数据，不作为额外授权。

交接新增 work/result/note 及 parentRequestId/replyToRequestId。结果由实际交接发起方处理，负责人整合最终业务，无需转发其他人的消息。负责人也可承担局部工作，其局部报告不覆盖整项业务。收件、工作报告、结果回传与 handledResults 分开校验；只有确认收到、旧报告、新结果未处理、受阻或整改均不算完成。原 completed 报告保留，但协作未完时显示协作待完成，不计待验收。验收另绑定协作证据版本。

**67/67 自动化测试通过，30 个 JavaScript 文件语法检查通过。** 新增检查覆盖能力快照、三人接力 A→B→C→B→A、四人双分支同找 D、局部工作回到负责人后继续分工、错接收方/错父请求、旧结果不能复用、缺少工作报告、受阻/整改和历史数据兼容。这些网状场景是隔离协议测试，不冒充三/四位原生员工的实机运行。

浏览器使用独立临时数据验证能力说明展开与勾选、B→C 由 B 处理且 A→B 仍待完成、证据入口、滚动及未完成时的验收限制。完成夹具经浏览器提交测试验收，计数从待验收 1/已完成 0 变为 0/1；该数据不在真实团队中。可运行 node tests/fixtures/collaboration.mjs 或追加 --complete 复现。
