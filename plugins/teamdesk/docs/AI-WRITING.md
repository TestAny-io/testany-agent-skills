# 表单 AI 撰写助手

## 已实现：部门职责、员工工作说明、任务目标与完成标准

使用现有桌面共享 App Server 中的专用原生任务。工作台保存撰写意图、结构化问题/答案、建议稿、来源版本和原生任务/轮次编号，不渲染完整对话。撰写助手不占员工名额，不生成业务任务，不向员工派发消息。

表单就地展开助手：一句话意图 → 按需查询资料 → 必要澄清 → 建议稿、假设/冲突和修改对比 → 用户采用到表单 → 原表单保存。用户可以继续要求缩短、补充交接条件；每次修改保留之前的建议稿。采用前检查表单名称、岗位、所属部门、技能及原文是否变化，防止用过时结果覆盖新编辑。AI 输入控件不参与原表单提交。

- 部门职责：负责范围、可接收工作、交付物、职责边界及交接条件。
- 工作说明：岗位和部门要求、所选 skill 的 frontmatter description、工作/交付要求、协作和升级条件；已有技能流程按引用使用。
- 新任务（0.0.7）：同一助手联动撰写目标与完成标准，参考用户选定负责人/协作者的技能 description、工作要求和相关部门生效资料；保持范围、排除项、交付物和协作安排一致。以未来可核验条件描述完成标准，不声称已经通过验收。
- 任务建议分成两个预览和差异区域，可选择采用一个或两个字段；未勾选项保留原文。采用后人工核对两项一致性，再使用原按钮提交。负责人、协作者或任一原文变更会使旧建议失效。仅服务新 FIFO 业务，steer 保持原输入方式。
- 草案仅为建议。无法核实的组织职责和权限明确列入假设；已知冲突必须展示。关键缺口最多提出三个简短问题；用户可以选建议答案或自由回答。
- 普通正文不会自动写入部门/员工；点击“采用到表单”也不会保存配置或派发工作。

## 接入与恢复

采用本机匹配的 `thread/start` 动态只读工具 `teamdesk_writing_context`、`teamdesk_local_sources` 和 `turn/start.outputSchema`。原生任务使用只读、禁网络沙盒、禁审批升级；任务级关闭 shell、apps、plugins、多智能体、浏览器、图片生成和 hooks 等非撰写能力，不修改全局配置。原生用户意图与建议留在原任务，可以从助手中的入口打开。

参考 [OpenAI App Server 文档](https://developers.openai.com/zh-Hans/docs/app-server)，具体协议以本机 Codex 0.155 生成 schema 和实机验证为准。动态工具为实验接口；同实例、权限和事件行为必须验证，不能用静态 schema 或假服务器代替真实执行。

每次点击持久化独立 client message ID 和幂等编号后按需生成。SSE 更新结果；没有模型轮询。连接或回执丢失时进入待核对，只读核对原消息/轮次，不自动重发。停止仅中断该助手的当前轮次。撰写记录与员工、业务任务及 hook 记账分开。

资料在每一轮建立参考快照，通过工具按需读取；默认只提供生效团队/本部门资料、同部门技能说明、其他部门职责/岗位。原表单未保存的选择优先用于本次撰写。此范围是组织信息与上下文控制，不宣称同一系统用户下的文件安全隔离。

## 本地资料（0.0.8）

直接在意图/补充中写仓库名、目录或文件路径。助手支持定位、列目录、搜索与按行读取；资料正文无需事先导入团队库。常见项目目录按名字查找，支持连字符/下划线与 docs/doc、users/user 差异；用户说明父目录时用于缩小候选。完整路径可直达；多个位置时在面板选择，缺失时补路径重试。

“本地参考资料”显示定位与读取状态。“参考依据”只显示工具真实返回的文件片段（完整路径、行范围、读取时间、文件 SHA-256），不能把搜索结果、模型声称或历史轮次视为当前已读取。未读到指定资料时保留待完善稿并禁用采用；用户可补路径、重试或明确“暂不参考这些资料，继续撰写”。跳过会记录和展示，未核实业务事实仍应保留假设。

每轮最多 16 个本地来源、100 条来源记录；读取普通 UTF-8 文本，单文件最多 2 MB、单次最多 200 行且 18,000 字符。搜索/目录响应有界；PDF、Office、二进制、隐藏配置/凭据与越界链接不作为此工具的文本资料，界面保留失败原因并允许更换资料。范围只由人类输入与选择确定，文件正文不能授予新的路径；本地读工具自身做检查，不能把原生沙盒当作自定义工具的保障。

旧版建议和输入不丢失。升级后若旧稿缺少要求的读取证据，显示待完善；继续时转接具备新版工具的原生撰写任务，历史中保留各轮原生链接。正在运行的旧任务先等待或停止，不抢占。该迁移只涉及撰写助手，员工任务保持原绑定和权限。

## 其他长文本入口评估

已按用户授权接入任务目标与完成标准；其余仅为评估。用户明确要求近期暂不接入工作约定／SOP。

| 入口 | 上限 | 适合程度 | 推荐交互与必要上下文 |
| --- | --- | --- | --- |
| 任务目标 / 要完成什么 | 12,000 字符 | 已实现（0.0.7） | 从一句意图整理目标、范围、输入、交付物和协作要求；参考负责人/协作者技能及相关资料。采用仍留在表单，原提交按钮才派发 |
| 完成标准 | 4,000 字符 | 已实现（0.0.7） | 基于目标给出可核验的完成条件。同一助手联动目标和标准，只填用户选择的字段 |
| 团队资料正文：工作约定 / SOP / 建议 | 20,000 字符 | 适合，但按用户要求暂缓 | 按资料类型和部门范围起草；参考生效约定，明确假设；保留现有保存草案→确认发布流程 |
| 团队资料正文：参考资料 | 20,000 字符 | 有条件适合 | 整理用户提供的原始材料并保留来源，不编造事实或出处；需要支持来源输入后再接入 |
| steer 补充内容 | 12,000 字符 | 适合，需约束范围 | 基于所选业务的目标/最新摘要，帮助表达补充或修正；提示与原目标的冲突；不自动改成新的业务或另派任务 |
| 退回整改说明 | 4,000 字符 | 适合辅助表达 | 将用户观察到的问题整理成问题、证据、期望修复和复验标准；AI 不凭空声称发现缺陷，不自动决定退回 |
| 验收通过说明 | 4,000 字符 | 只适合用户先表态后的润色 | 根据用户已经选择的结论组织文字；不让 AI 代替用户判断通过、宣称验收或编造验证证据 |
| 待你决定的回答（业务 / 原生问题） | 每项 4,000 字符 | 不宜直接套用“AI 帮我决定” | 可解释选项或润色用户已表达的决定。原问题、选项及必要上下文是前提；私密输入和原生审批沿用原流程 |

任务目标与完成标准已交付；其余入口等待后续范围决定。人类决定和验收入口需要独立的辅助决策设计，不应仅因为是长文本框就统一加生成按钮。系统内置协议继续由版本维护，没有编辑入口。
