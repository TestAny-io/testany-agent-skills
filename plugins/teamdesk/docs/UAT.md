# TeamDesk 0.3.0 UAT

新用户从 [种子测试指南](SEED-TESTING.md) 开始，先验收安装和首次共享接入，再按下面清单测试。默认 http://127.0.0.1:4322/#overview，仅在本地服务运行时可访问。

连接目标必须是当前 Codex Desktop 实际使用的同一个 App Server；需要共享启动时按设置提示正常退出，再通过 TeamDesk 图标启动。新安装为空团队，没有预置测试员工。升级保留已有业务，当前版本尚未收到原生 hook 回执的员工会显示待接入，可在正常工作或手动入职检查后更新。

以下按原迭代列出延续验收项目。历史工程验证不代替你的业务验收；完整范围见 [VERIFICATION.md](VERIFICATION.md)。

## 0.3.0 安装兼容性修复

1. 在此前无法打开图标的 Mac 上重新运行统一安装入口；四步通过，插件与图标版本均为 0.3.0，已有团队数据保留。
2. 按 [只读诊断](SEED-TESTING.md#4-macos-拒绝打开图标) 核对两个程序的 `minos` 均为 13.0，架构与本机匹配；安装回执中也应有相同的 compatibility 记录。
3. 双击新图标，确认 Finder 不再拒绝启动，再按下方冷启动项目核验 Codex 窗口、Safari 与共享连接。安装检查通过不能代替此步。

## 0.0.13 本轮重点

1. 在“协作消息”打开“投递与回执”，核对本地登记、原生接受、输入、员工领取、报告、关联结果及发起方处理。缺失时间须显示未确认，不能把所有等待称为网络延迟。
2. 打开“协作视图”，按任务和部门筛选；跨部门参与者保留。同一员工可以直接联系多位同事，不要求经负责人中转。点选员工、箭头、交接卡查看证据和原生链接。
3. 播放/暂停历史、上一步/下一步、点时间线、回到实时；员工后来改名/转部门/换绑不得改写旧快照。升级前仅有初始基线，旧 hook 迟到更新标为补充观察。
4. 部门折叠、缩放重置、触控板滚动；窄屏详情出现在图下方。任务和交接卡各显示最近 12 项，更多信息用筛选和消息列表查看。
5. 团队设置分别显示“同实例连接”与“状态恢复”，单员工失败明确归属；未知投递不得因重连自动重发。查看阶段耗时与错误，系统接受窗口打开请求不能冒充窗口实际可见。

## 启动图标仍需复验的真实冷启动

0.0.11 的真实冷启动 UAT 已由用户报告失败：启动前插件查询报错、Codex 仅在后台、Safari 未打开。该项不能视为已通过，0.0.12 修复后需要重验以下路径。

0.0.12 一键图标验收：

1. 正常退出 Codex，双击桌面 TeamDesk 图标（或拖入 Dock 后单击）：Codex Desktop 与 Safari 工作台应一起打开，团队设置显示已连接同一 App Server。
2. 已共享连接时再次点击：复用 Codex 和 TeamDesk 服务，不新增员工任务。
3. Codex 以普通方式运行时点击：Safari 打开团队设置，图标提示正常退出再点；当前 Codex 及任务继续运行。
4. 停止 TeamDesk 服务再点击：服务恢复，员工/任务/请求保留；反复点击不启动第二个服务。
5. 升级插件后，原图标应找到当前安装版本；后续 Codex 版本仍需实际握手，不因版本较新直接拒绝。

本轮不会为了验收强行关闭当前 Codex。真实冷启动整个 Codex 的步骤留给用户在正常退出后执行，详见验证记录。

0.0.10 版本门槛验收：数字版本基线 ≥0.155.0（含预发布版本）；新 minor/major 不再仅因版本较新被拒绝。低版本或无法解析的版本显示明确原因；仍要求同实例连接及真实原生回执。更高版本的边界比较由测试覆盖，尚未做对应新宿主的实机联调。

0.0.9 员工模型设置验收：

1. 打开员工详情 → 模型与运行偏好，应显示与 Codex 一致的模型、思考深度、速度及同步时间。
2. 保存一组当前模型支持的档位，只有读回一致才显示成功；Fast 关闭应实际清除原生速度覆盖。
3. 切换模型，可选深度与速度同步变化；不支持的选项调整时有说明。
4. 在 Codex 原生界面修改同一会话设置，工作台同步显示；已打开且过期的设置表单应保留选择并要求刷新。
5. 员工工作中仍可更改默认值；当前轮次继续使用原配置，后续轮次（含排队任务）使用新默认。此操作不会新建业务或通知员工。
6. 断线显示最近同步值并禁止保存；恢复后刷新核验。换绑后显示新会话配置；任务的临时覆盖入口显示 Coming soon。
7. 点击任务级 Coming soon 保留已输入的目标与标准。新员工首次初始化前如未生成原生历史，应提示等待入职检查，不产生假任务。

当前原生限制：CLI 0.155.0-alpha.9.2 的实测中，Fast 在会话冷加载后曾恢复为标准速度。工作台显示实际读回值及与上次保存不同的提示；不承诺 Fast 在冷加载后持久保留，不用静默重写绕过此行为。

0.0.8 本地资料修复验收：

1. 在部门职责、工作说明或新任务助手中直接写参考仓库名/完整路径；确认能读取正文，来源列出文件、行范围、读取时间和版本。
2. 引用不存在的资料：状态为“参考资料尚未读取，当前稿待完善”，已生成文字保留，“采用”不可点；填写正确路径后重试可继续。
3. 同名目录出现候选；选择后重试；也可明确暂不参考未读资料，确认界面标记此选择。
4. 旧撰写保留既有要求和建议；继续后新版工具读取指定仓库，各历史轮次仍可打开原生记录。
5. 建议采用只回填表单；检查原始部门/员工配置和业务任务在点击原保存/提交按钮前不变。

0.0.7 新增任务撰写验收：

1. 新建任务，选择负责人和协作者，填写已有目标/完成标准；点击“AI 帮我写／完善”，用一句话补充意图。即使原文留空也能先请助手起草。
2. 查看必要澄清问题并回答；建议稿分别展示目标、完成标准和修改对比。核对既有范围、排除项、协作要求及生效约定被保留，标准不扩大目标范围。
3. 要求进一步精简，确认同一撰写任务继续、历史两项建议保留。
4. 只勾选目标或只勾选完成标准再采用，另一字段原文不变；同时勾选时两项都回填。采用后依然在原表单，可以继续人工编辑，任务计数/请求数不增加。
5. 修改原文、完成标准、负责人或协作勾选后，旧建议不能采用。切换 steer 后助手隐藏，切回 FIFO 原表单文字保留。
6. 最后点击原“保存并交给 Codex”，才出现新任务；检查保存目标、完成标准、负责人和协作者准确，助手意图/勾选控件没有混入任务字段。
7. 正常部门职责/工作说明助手仍可使用；团队资料中的工作约定／SOP 保持原编辑方式。

0.0.6 新增 AI 撰写验收：

1. 新建或编辑部门，点击职责下方“AI 帮我写／完善”，填写一句意图；检查能参考相关部门职责、发现冲突，并仅在关键缺口处提出短问题。
2. 选择建议答案或自由回答；查看建议稿、待确认假设、冲突和原文修改对比。对存在假设/冲突的建议，需先确认已审阅才能采用。
3. 要求“简短一点”或补充交接条件；确认沿用同一 Codex 撰写任务，之前的建议在“撰写历史”中保留。
4. 生成期间修改原文、岗位、部门或技能，旧建议不能直接覆盖新编辑；可以基于当前表单重新生成。
5. “采用到表单”只填入文本；取消原表单不改变部门/员工，点击原“保存”按钮才生效。其他未保存字段及技能选择不丢失。
6. 在新增/编辑员工时选择技能后生成工作说明，检查参考所选技能 description 和部门职责。未绑定 Codex 员工任务前也可撰写，不新增员工或业务。
7. 收起/重新打开助手可恢复该表单本次撰写；连接中断保留表单和请求，“核对结果”不重发模型输入。“停止生成”仅停止该撰写轮次。

其他长文本字段的评估见 [AI-WRITING.md](AI-WRITING.md#其他长文本入口评估)；0.0.7 在上述两个入口基础上增加任务目标与完成标准，工作约定／SOP 暂缓。

0.0.5 新增资料管理验收：

1. 新建/编辑普通资料先保存草案；从卡片或详情点击“发布草案”，核对内容与适用范围后确认发布；修改草案期间员工仍使用上一生效版。
2. 卡片/详情点击“删除资料”：取消保持不变，确认后退出在用列表和员工查询；筛选“已删除”可查看正文及完整历史。
3. 从已删除或旧归档资料“恢复为草案”：编号、内容、部门范围及历史保留，重新发布之前员工不可查询，包括显式请求旧版本。
4. 系统内置协议显示只读原因，只提供查看入口；团队约定及普通 SOP/参考资料可以编辑、删除、恢复。
5. 删除或恢复期间的过期操作提示重新核对；重复提交不多生成版本。删除资料不会删除或改变已有任务及其引用。


0.0.4 新增组织管理验收：

1. 部门列表和详情始终提供“删除部门”；空部门可直接确认，有员工时必须选择全部转入其他部门或移出为未分配，取消应无变化。
2. 从部门成员列表、员工卡片/详情转部门；从成员列表或详情移出。检查旧联系人清空，员工身份、技能、会话、正在处理的任务和历史保留。
3. 员工页筛选“未分配部门”，可以重新分配；多个未分配员工不被当作同部门。
4. 删除后在用列表、员工部门下拉和员工查询不再出现；“已删除部门”中可以恢复。恢复保留职责与原 ID，不把已转走或移出的员工拉回来。
5. 原部门资料仍保留供人类查阅；转部门不自动迁移资料。编辑已删除部门资料时不能误选成全团队。
6. 两个窗口同时操作同一员工或部门成员，过期确认需拒绝并提示重新核对。

以下为 0.0.3 延续验收：

1. **部门**：检查原分组已迁移、原员工与任务仍在；填写职责、设置联系人，移动成员后核对联系人约束。
2. **团队资料**：新增 SOP 草案→发布→修改并保存草案，确认员工仍读前一生效版；检查历史、部门范围、删除/恢复及旧归档兼容。
3. **员工查找**：让员工查询同部门技能描述及其他部门职责/岗位，确认跨部门不展开技能详情。
4. **精简上下文**：在 Codex 查看新输入，只有本次请求与资料入口；员工使用 query 按需读取，不领后续 FIFO。
5. **验收反馈**：通过时填写说明，查看负责人原生接收与确认回执，已完成计数不回退；退回时收到整改说明，同一业务继续处理。

## 建议先验收这条路径

1. **团队设置**：查看共享连接、版本与 hook。打开「审查共享 hook」，能看到定义、命令、脚本和信任状态；已信任时无需重做。
2. **员工**：添加或绑定一位员工，填写任意岗位/部门，选择技能；建议先建立专用测试员工。选择新建会话时，Codex 中应出现对应会话，入职完成后显示记账就绪。
3. **任务**：提交一项真实业务，指定负责人；协作者用普通点击复选框选择。应立即出现保存、原生排队/接受、接收等进度，无需等定时任务。
4. 员工处理 A 时，再提交独立的 **FIFO B**，并给 A 提交 **steer 补充**。B 在原生队列等待，补充进入 A；若 A 已结束，补充成为同一业务的新轮次。
5. 请员工使用原生结构化提问。问题应在本轮结束前进入「待你决定」和总览；回答后先显示已提交，收到原生证据后显示已决定。
6. 仅在派发时勾选协作者，业务正文不额外要求“必须联系某某”。员工应按任务目标与技能主动安排协作。查看双方 Codex 会话的可见发送说明、消息、真实回信和结果处理；工作台显示对应 metadata 与摘要。也可让 B 继续找 C，C 的结果由 B 处理，负责人 A 整合最终交付。
7. 负责人交付后下载产物，再由你决定通过或退回。负责人 completed 与你的验收分别保留；首页和任务页的「待验收」「已完成」显示对应数量，点击可筛选任务。已完成只计当前交付版本验收通过的业务。
