# 共享 App Server PoC

历史 PoC 报告；下文集成待办反映测试当时状态。后续 MVP 已集成共享接入，现行说明见 [README](../README.md)，本报告不替代当前版本验证。

日期：2026-09-17。核心按需链路通过；正式 TeamDesk 尚未集成。

## 已证明的架构

桌面 Codex 启动自己的 App Server，TeamDesk 本地接入器作为第二个客户端连接同一个进程。员工沿用已有任务 ID、目录、已安装技能、插件、原生工具和 hook 信任。网页通过本地接入器提交输入、接收 metadata；原生任务按需要调用 codex-app-tools。

本次用临时的 stdio/WebSocket 适配器完成连接：桌面正常传入启动参数和原生插件环境，适配器只转换传输；底层仍为桌面附带的 App Server。通过实际进程父子关系、双客户端连接、诊断 PID，以及真实原生任务执行验证同实例。没有使用第二个独立运行环境恢复同一员工。

实测版本为 **Codex 26.911.61220 / CLI 0.155.0-alpha.2.6**。切换前调查版本较旧，实际重开后重新读取了版本并生成当前协议 schema。这不是跨版本回归测试。

## 验证结果

| 项目 | 结果与证据 |
| --- | --- |
| 普通本地 GUI 按需提交 | 用户真实点击按钮，服务调用共享实例的 `turn/start`；原生事件记录同一提交 ID、任务 ID 与轮次，产生严格匹配的 ACK；SSE 页面展示 metadata。用户确认网页和原生任务均可见。 |
| FIFO | 活跃轮次中通过 `thread/queue/add` 加入独立任务。前一轮完成后，原生队列自动启动下一轮；两轮 ID 不同且顺序正确。 |
| steer | `turn/steer` 的有效 `expectedTurnId` 将追加要求送入同一轮；错误轮次 ID 被拒绝。最终回复反映追加要求。 |
| 重复请求 | 同一 `clientUserMessageId` 重复 `thread/queue/add`，实际生成两条队列记录。原生队列没有本次所需的幂等保证。多余测试条目已精确移除。 |
| 已安装技能 | 测试员工实际通过工具读取 Internal Agent Guide 及分类参考，完成一个有明确交付物的分类工作。读取调用与对应真实输出均已核对。 |
| 原生双向通信 | Observer 用原生 codex-app-tools 联系 Reviewer；Reviewer 用同一原生能力回信。两端原生 FunctionCallOutput 的发送来源、接收标记和最终完成消息均可关联。 |
| 人类问题 | 员工发出原生结构化问题，用户真实选择 BLUE。原生回答和最终确认在同一轮；正式 TeamDesk 的决定 metadata 也变为 resolved，来源为 human_native。 |
| Stop hook | GUI 输入、FIFO、steer、技能交接、问答与重连测试的原生轮次均产生唯一的 TeamDesk hook 回执，状态 saved；未更改信任。技术探针没有伪造业务工作记录或验收。 |
| 外部客户端重连 | 空闲时和执行命令过程中均实测断开/重连；进程 PID 不变，运行中恢复到相同轮次，并正常完成。 |
| 权限审批 | 在专用测试员工临时收紧权限后，真实命令审批请求同时到达桌面客户端和外部客户端，任务/轮次归属一致。两次探针均在等待时限后由控制器中断；没有取得人工点击后的完整回传证据，不能计为人工拒绝。测试权限已恢复并由另一个客户端读回，两个员工 idle、队列为空、测试文件未写入。 |

本机可重放核验程序只读取原生事件及 TeamDesk 数据库，生成派生报告。私有任务 ID、路径、原生记录和截图保存在 Git 忽略的 `output/` 中，不进入插件发布内容。

命令审批尚未进入正式工作台的决定列表。本次确认的是共享连接中的请求路由与测试网页的等待状态 metadata；正式“需要你的决定”条目和真实人工决定回传仍需补齐验证。用户选择 BLUE 的结构化问题属于已经完整通过的另一条路径。

## 实测发现的接入细节

1. **显式选择投递语义。** FIFO 使用原生队列，steer 使用当前轮次 ID；不要把所有输入都发给 `turn/start` 并期待自动获得 FIFO。
2. **应用必须防重。** 在发送前持久化唯一操作 ID 和状态，序列化同一操作的投递。断线或超时发生在发出请求之后时，先核对原生回执/队列/输入记录，再决定是否重试。不能因 HTTP 重试直接再入队。
3. **订阅与恢复需要处理。** 新客户端能收到全局状态，不意味着已订阅所有任务的详细事件。接入器应明确需要的任务订阅，断线后重建关联并核对历史 metadata，不重复派发模型任务。
4. **启动适配器只能作用于桌面主进程。** 初版启动路径被浏览器辅助检查继承，导致辅助进程误连同一端口。修正为仅匹配真实桌面主进程，其他 CLI 调用照常透传，并避免向底层辅助进程传播实验环境变量。修正后浏览器安全检查和页面读取恢复，未关闭或绕过检查。
5. **设置更新必须读回。** 对已加载任务，仅调用 `thread/resume` 附带权限 override，在本次实测中没有恢复临时设置。使用 `thread/settings/update` 后再读取实际权限配置，才能确认恢复；设置请求返回成功不是状态已改变的证据。

## 产品接入建议

共享 App Server 值得作为普通本地 GUI 的主要接入路线：输入提交直接触发原生工作，无需定时唤醒接入任务。原生托管 UI 的消息桥保留为另一候选。

正式集成仍需交付：可靠的本地连接管理、持久防重/结果不明处理、完整的 FIFO/steer GUI、问题/审批 metadata 的归属与恢复、版本兼容检查、启动失败和退出/回退流程。不能把这个 PoC 适配器直接当成安装完成的 MVP。

本次没有宣称 32 员工同时满负荷运行、所有第三方插件逐一兼容，或完整桌面退出/回退压力测试已通过。当前临时启动没有写入全局启动项；正常退出后以普通方式重新打开 Codex，会使用默认连接方式。恢复脚本已准备，实际是否演练以本机报告为准。

协议和传输说明参见 [OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)。本次使用的桌面启动开关来自本机实现观察，不能据此宣称它们属于稳定公开配置；WebSocket 传输也应按官方标注的实验性支持范围管理。
